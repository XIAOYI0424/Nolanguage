## 一、P1 · 测试运行器（约 2d）

### 1.1 做什么 / 不做什么

做：一个 `Tests` 底部面板，树形（包 → 文件 → 用例），点单个用例只跑它，失败项进 Problems 并可跳行，可取消。

不做：不做新运行时（`run.modes.test` 已经能跑测试）、不做覆盖率高亮、不做 watch 模式、不做多语言解析器（先 `go-test` 一个，`parse` 是数据，后面加 `pytest` 只加纯函数）。

### 1.2 协议面

### 1.4 门禁（每条都能红）

| 层 | 断言 | 注入验证（必须红） |
|---|---|---|
| 单测（`tests/`） | `parseGoTest` 认 pass/fail/skip/子测试；交错并行输出不串用例；半行跨 chunk 正确；垃圾输入返回 `output` 而不抛 | 把 `--- FAIL:` 分支删掉 → 失败用例数为 0 |
| 引擎（`verify:ide`） | `testRun` 回 `testStart`（带真实 `command`）→ 至少 1 个 `testCase` → `testResult` 计数自洽；`testCancel` 后 `cancelled: true` 且不再有 `testOut` | 去掉 `signal` 传参 → 取消断言红（进程不退出） |
| 纯 UI（`verify:ui`） | 点某个用例节点发出的 `testRun.filter === '^TestFoo$'`（不是整包）；收到 `testCase{status:'fail'}` 后 `#probOut` 出现该用例名；**先注入一条 `diagnostics` 再收 `testResult`，断言两条都在**；切到别的语言时 `testOut/testCase` 帧被丢弃 | 去掉 `filter` 透传 → 第一条红；`setDiags` 整体替换 → 第三条红（诊断被冲掉） |

### 1.5 风险

- `capture()` 是"一次性 Promise"，要拿到 `testCase` 流式必须先有 `onData` 行缓冲（1.3 第 6 条的增量解析器），否则只能在结束时一次性刷出整棵树 —— 那就失去了"边跑边看"。
- go 的并行子测试（`t.Parallel()`）输出会交错，解析器必须允许"`--- PASS` 出现在 `=== RUN` 之后任意位置"，只按名字关联合。
- `BOTTOM_WINDOWS` 的 `key` 已经比较拥挤（`run` 是 Alt+4、`packages` 是 Alt+6），先看 `70-shell.js` 有没有现成空位，没有就用菜单入口，别硬塞。

## 二、P2 · Inlay Hints（约 1.5d）

### 2.1 做什么 / 不做什么

做：LSP `textDocument/inlayHint` 的六段链（客户端请求 → 引擎 → LSP → 归一化 → 回帧 → 渲染），只请求视口范围，能力缺失时静默。

不做：不做类型推演（那是 LSP 的事）、不做参数名的本地猜测、不持久化。

### 2.2 协议面

| 方向 | kind | 字段 |
|---|---|---|
| C→E | `inlayHints` | `{ language, requestId, code, fromLine, toLine }`（0-based，闭区间） |
| E→C | `inlayHints` | `{ language, requestId, hints: [{ line, character, label, kind?: 'type'\|'parameter', paddingLeft?, paddingRight? }], unsupported?: string }` |

`unsupported` 走 folding 的模式（显式原因、前端静默），**不要**照 hover 的 silent-null（`WorkspaceService.ts:1078` 那种把"能力缺失"和"此处无内容"混在一起的做法）。

- `kind` 的 LSP 约定是 1=Type、2=Parameter，别写成字符串枚举直接透传。

## 三、P3 · 插件市场：sha256 校验（约 0.5d；UI 列表另算 1d）

### 3.1 做什么 / 不做什么

做：`lang add <id>` 拿到 index 条目后，下载完成必须校验 `sha256`；不匹配就中止且不留半装目录；没有 `sha256` 的条目在 `--strict` 下拒绝。

**不做签名验签**：仓库里既没有发布密钥，也没有轮换/吊销机制。`sha256` 只能防传输损坏与镜像篡改，防不了"index 本身就是恶意的"——这一点要写进 `/plugins` 页的提示，而不是假装已验签。`manifest.trust.signature`（`manifest.ts:263`）目前只校验枚举值（`:553`），保持现状。

- `DEFAULT_INDEX_URL`（`Catalog.ts:59`）是占位域名，没有真实服务端。所以 UI 这一半**先按"不可达"路径做完整**，否则上线当天是一片空白。

## 四、P4 · AI 侧栏（先出协议，代码约 2–3d，暂不排期）

### 4.1 现状硬约束（这四条决定它是"先设计"而不是"接线"）

| 约束 | 证据 |
|---|---|
| 引擎没有任何出网 API 客户端 | 唯一的 `http/https` 用法是插件下载器 `SourceResolver.ts:40`（带 maxBytes/超时/重定向上限，不是通用 client） |
| 没有密钥存储 | 前端 `PREFS` 是 localStorage 明文（`10-state.js:5`，键 `nolanguage.pycharm.v1`）；引擎侧只有 MCP 的 `appDataPath('mcp.json')`（`McpManager.ts:176`） |
| 日志会把字段原样落库并进全文索引 | `PanelHub.pushNewLogs`（`:422`）→ `SqliteStore.insertLogs`（`:255`），`fields_json` 参与 FTS。`src/log/` 内 `redact\|secret\|mask` 零命中 —— 没有脱敏工具，只能靠"绝不记录" |
| 没有取消原语 | `capture()` 支持 `AbortSignal`（`proc.ts:43`），但 HTTP 侧没有；最接近的模板是 `McpManager` 的 pending-timer（`:416-470`） |

### 4.2 第一步（0.5d，纯文档）

`docs/ai-panel-protocol.md` 定清四件事：

1. 帧：`aiAsk {requestId, prompt, language?}` / `aiOut {requestId, text, done?}` / `aiDone {requestId, ok, ms, error?}` / `aiCancel {requestId}`。
2. 配置：`appDataPath('ai.json')`，形如 `{ baseUrl, model, keyRef }`；密钥不进 `PREFS`（localStorage 明文，任何扩展/脚本都能读）。
3. 日志禁区：prompt / 响应 / 密钥**一律不走 `logger.*`**，需要留痕只记 `{requestId, ms, bytes, ok}`。
4. 范围：不做多轮上下文持久化、不做代码库索引、不做工具调用（MCP 已有独立一套）。

### 4.4 门禁

| 断言 | 注入验证（必须红） |
|---|---|
| 本地假 provider（`127.0.0.1` 起 `node:http`，返回 3 个 SSE chunk）→ 客户端按序收到 3 个 `aiOut` + 1 个 `aiDone` | 把 `requestId` 关联去掉 → 顺序断言红 |
| `aiCancel` 后不再有任何 `aiOut`（等服务端超时窗口再断言一次） | 不 abort → 断言红 |
| 假 provider 收到的请求里不含日志痕迹：`SqliteStore` 全表搜 `sk-test` 命中 0 | 用 `logger.info` 记一次 prompt → 断言红 |
| 密钥未写入 localStorage：`PREFS` 序列化后不含密钥 | 用 `savePrefs({aiKey})` → 断言红 |

### 4.5 风险

- 这是四项里唯一"协议未定"的：**不要先写 UI 或先写 provider**，否则会返工两次。
- 如果真实 provider 在境外，网络不可达时的错误必须说清楚（"地址不可达"而不是"AI 无响应"），否则会被当成 bug 排查。
