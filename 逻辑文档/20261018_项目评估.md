## 3. 架构评估（优点）

1. **语言零硬编码**：`manifest.json` 驱动扩展名、语法高亮、运行方式、LSP、调试、剖析；`RunnerFactory` 只按 `run.mode` 派发。新增一门语言不用改引擎代码，这个设计在 4 个插件上验证过。
2. **传输可替换**：WebSocket 与 stdio 两条传输共享同一份协议与 UI，`verify-transport.ts` 有 19 条等价性断言——Tauri 化没有分叉出第二套前端。
3. **Rust 只做管道**：不解析 `kind`，所有语义留在可测试的 TS 侧；fork bomb 防护（拒绝解析到自身的 sidecar 路径）是自己踩坑后补的。
4. **可观测性是内建能力**：CommandBus/EventBus/ServiceRegistry 天然埋点，PerfSpine + LogSpine + SQLite 温层 + baseline，不依赖第三方 APM。
5. **零运行时依赖**：整个 IDE（编辑器、语法高亮、文件树、对话框）都是自绘，安装包不携带 Chromium/Node 之外的东西。

## 4. 主要缺陷（带证据）

### ~~P0-1 `npm test` 完全不可运行~~ —— 已修复（9/9 通过）

```
修复前：FAIL tests/phase1.test.ts · Failed to load url sqlite · 1 failed | no tests
修复后：✓ tests/phase1.test.ts (9 tests) · Test Files 1 passed · Tests 9 passed
```

根因：`src/store/SqliteStore.ts` 的 `import 'node:sqlite'`。Vite 5（vitest 1.x 的 bundler）内置模块表早于 `node:sqlite`，于是把 `node:` 前缀剥掉、当作普通包解析，收集阶段就崩。

修法（`vitest.config.ts` + 一个 stub，三层）：

| 层 | 配置 | 作用 |
|---|---|---|
| 外部化 | `ssr.external: [/^node:/]` | 阻止 Vite 尝试转换 `node:*` |
| 别名 | `resolve.alias['node:sqlite'] → tests/stubs/node-sqlite.ts` | 即使前缀被剥掉，也解析到 stub 而非磁盘上的 `sqlite` |
| 隔离 | `pool: 'forks'` | `node:sqlite` 持有原生句柄，fork 进程更稳 |

stub 只在"真的去查询"时抛错并说明原因（"unit tests run without a database"），避免未来 SQLite 测试假通过。

        src/panel/{profile-ui,perf-ui,ui}.ts 各 3 · src/log/LogSpine.ts 3
        src/perf/PerfSpine.ts 3 · src/demo.ts 3 · …
修复后：tsc --noEmit → exit 0，0 errors（CI 步骤已去掉 continue-on-error）

根因与修法（按类型分类）：

| 类别 | 例子 | 修法 |
|---|---|---|
| 缺失模块声明 | 9 个 `import page from './ui.js?raw'` | 新增 `src/panel/raw.d.ts` 声明 `*?raw` |
| 类型名不存在 | `import type { IKernel }`（实为 `Kernel`），`LogSpine` 还导错了路径 | 改导入名与路径 |
| 参数逆变 | `CommandHandler = (...args: unknown[])` 拒收具体签名的处理器 | `CommandBus.register` 泛型化 `<A extends unknown[], R>` |
| 类型比实现窄 | `KernelOptions.store` 缺 `string`，而实现已按字符串路径处理 | 类型补 `string` |
| 语义反向 | `hello.levels` 需要"名称→数值"，却传了 `LOG_LEVEL_NAMES`（数值→名称） | 新增 `LOG_LEVEL_VALUES` |
| 真实漂移 | `PythonProfiler` 读了 `parsed.flame`，但解析结果类型里没有 `flame` | 补 `RawFrame` 与 `flame?: RawFrame[]` |
| 重复导出/导入 | `index.ts` 两处导出同名类型；`demo.ts` 重复导入 `SqliteStore` | 内核版加 `Kernel*` 别名；删重复导入 |

影响消除：`strict` 现在真正生效，`flame` 那类"类型与实现漂移"会被编译器挡住。

### P1-1 CI 不覆盖分发路径

CI 只做：typecheck（advisory）→ `build:exe` → `verify-all`。
不做的：`npm test`、`npm run build:setup`、Tauri 打包、安装后 smoke（静默安装 + `/health`）。
本轮安装器的所有验证（目录页、进度条、无控制台、sidecar 启动）都是手工 UI Automation 完成的，没有沉淀成 CI 步骤。

### ~~P1-2 前端单体~~ —— 已修复（2,935 → 110 行 + 三个分层文件）

拆分方式：纯行切片，输出 HTML 与拆分前一致（`verify-pycharm` 172/172 不变）。

| 文件 | 行数 | 职责 |
|---|---|---|
| `src/panel/pycharm-ui.ts` | **110** | 装配：token 模式、示例工作区、图标几何 + 一次字符串拼装 |
| `src/panel/ui/pycharm-css.ts` | 425 | 整套样式表（两个主题都是变量翻转） |

`pycharm-client.ts` 仍是单文件：脚本共享一个闭包（状态、helper、事件绑定），继续拆需要把状态穿参，收益不明显；文件头按执行顺序列出了 27 个分区，注释里注明"为什么不再拆"。反引号事故的根因（注释写在模板字符串里）随 CSS/骨架外提减少了约 70% 的面积。

### P1-3 两条分发路径的长期成本

| 形态 | 安装包 | 向导语言 | 安装路径 |
|---|---|---|---|
| Node SEA | `installer/Nolanguage-Setup.exe` | 中文 | `Programs\Nolanguage` |
| Tauri 壳 | `bundle/nsis/*.exe` | 英文（默认模板） | `Nolanguage` |

两者都可用且实测通过。原缺陷是引擎镜像靠手工复制（`dist/Nolanguage.exe` → `src-tauri/binaries/…`），漏一步就会出现"壳新引擎旧"（本轮已发生过一次：安装包里打的还是旧二进制）。

**已修复**：`scripts/sync-sidecar.mjs` 按 sha256 比对后复制，`tauri.conf.json` 的 `beforeBuildCommand` 自动调用它；`npm run verify:sidecar` 只校验不写入（差异退出码 1），可进 CI。实测第一次 `--check` 就抓到了真实漂移（`dist=aff857d4…` vs `sidecar=1dad23c5…`），同步后复检通过。

## 5. 值得肯定的工程习惯

- **验证脚本按阶段编号**（stage1→10 + 各子系统），每个脚本自带断言计数，失败即退出码非 0，适合 CI。
- **注释记录"为什么"而不是"是什么"**：例如 `engine.rs` 为什么不用插件默认的名字查找、`pycharm-ui.ts` 为什么要拦截 `contextmenu`、`RunnerFactory` 为什么只有一个分支。
- **踩坑留痕**：fork bomb（180 进程/15 秒）、`node:sqlite` 的实验性、SEA 的 console 子系统、大小写不敏感文件系统下 sidecar 与主程序同名——都写进了注释或文档。
- **依赖纪律**：运行时依赖只有 1 个，构建工具（esbuild/postject/jsdom）装在项目外的隔离 workspace，`package.json` 不被污染。

## 7. 结论

- **技术选型与架构是高质量的**：微内核、插件化语言、可替换传输、内建可观测性，这套骨架支撑了 4 门语言、两套窗口宿主和两条分发路径，没有出现"改一处崩一片"的迹象。
- **闸门已从"靠人"变成"靠机器"**：`npm test` 9/9（vitest 配置 + `node:sqlite` stub）、`tsc` 0 错误（CI 阻塞）、`verify:sidecar` sha256 校验、CI 覆盖"单测 → 构建 → 1332 断言 → 打包 → 静默安装 → `/health` → 上传产物"。
- **镜像漂移从物理上消除**：`build:exe` 的 `postbuild:exe` 钩子 + `tauri build` 的 `beforeBuildCommand` 双入口同步，`verify:sidecar` 可单点校验。
- **唯一未落地项是 eslint**：本机 `npm view eslint version` 无响应（registry 不可达），无法安装依赖；规则集与 CI 步骤需在联网环境补。
- **发布建议**：可以支撑持续分发。剩余收益主要在 lint（`no-floating-promises` 这类静默缺陷）与把 `pycharm-client.ts` 的 27 个分区逐步抽成独立字符串模块。
