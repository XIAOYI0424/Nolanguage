> 生成日期：2026-10-21
> 范围：Rust 外壳（`src-tauri/`）、Node 引擎（`src/`）、语言插件（`builtin/`）、PyCharm 外壳（`src/panel/ui/`）

## 0. 先把「无感迁移」定义清楚

「看起来像 PyCharm」和「PyCharm 用户能无感转过来」是两件事。后者要求**打开现有工程即可用、零重配置、手感一致、且不破坏原工程**。可验收为 5 条：

| # | 无感标准 | 现状 |
|---|---|---|
| A | 打开已有项目目录，**自动识别解释器/虚拟环境**，Shift+F10 直接能跑 | ❌ 无 venv/conda 探测 |
| B | 原有 **Run/Debug 配置**（`.idea/runConfigurations/*.xml`）自动出现 | ❌ 完全不读 `.idea` |
| C | **快捷键手感一致**（Ctrl+B、Alt+F7、Shift+F6、Alt+Enter、Ctrl+F…） | ❌ 多项未绑定 |
| D | **调试体验对齐**（变量/监视/调用栈/断点持久化） | ❌ 只有栈帧文本 |
| E | **测试**能在 gutter 一键跑（pytest） | ❌ 无测试运行器 |

结论：当前是「高保真 PyCharm 外观 + 真实可用的 Run/Debug 骨架 + 部分语言智能」的轻量多语言 IDE，**距离无感替代缺的是 5 条核心价值线**，其中 A/B/C 是「迁移门槛」，D/E 是「留住用户」。

## 1. 现状盘点（2026-10-21）

### 1.1 已真实可用（保持，不要动）
- 自绘 PyCharm New UI 布局、expui 图标、Darcula 默认主题、可切换 Light。
- 真实文件系统：Project 树 `fsList`、打开/保存/新建/重命名/删除（`fsRead/fsWrite/fsCreate/fsRename/fsDelete`）、多标签 + 脏标记 + 持久化。
- 配置驱动的 Run/Debug：`normCfg`（`name/path/language/cwd/args/env/stopOnEntry/request`）+ `editRunConfigs` 弹窗 + `program/serverReads/args/env/cwd` 全链路（`src/panel/ui/pycharm-client.ts:3209-3300`、`src/panel/server.ts:1250-1420`）。
- 调试条 5 键（Continue/Step Over/Step In/Step Out/Stop）+ 按文件断点（`pycharm-client.ts:1799-1804,431-432`）。
- 适配器缺失时给具体安装命令（`install` 字段，Python→`pip install debugpy`，Go→`dlv`）。
- LSP：completion / hover / diagnostics 三方法；补全与 hover 已接线。
- 终端（管道式，可交互 `input()`）、Problems、Logs、Performance、Coverage(Python)、Profiler(Python cProfile/Go pprof)、Search Everywhere 外壳、MCP 工具窗。
- 质量门禁 `npm run verify`（30 套件，含真 DAP/LSP 子进程）与 `verify-dap` 21 项。

### 1.2 关键缺口（均为代码事实）
| 领域 | 缺口 | 证据 |
|---|---|---|
| 迁移互操作 | 不读 `.idea/`（被列入跳过目录）、不读 runConfigurations XML、不读/写 `launch.json`、无迁移向导 | `src/panel/FsService.ts:88-101` |
| 解释器 | 无 venv/.venv/conda/pyenv 探测；无解释器选择器；`versionFiles` 未声明（`.python-version` 不生效） | `builtin/*/manifest.json` 无 `versionFiles`；`src/panel/server.ts` discovery |

| 调试 | 无变量树/作用域/Watch/Evaluate/可点击栈；无 Pause/Restart；`attach` 当 launch；断点无持久化/无条件/无列表 | `server.ts:1347-1412`、`pycharm-client.ts:2345-2347,1316-1317` |
| 测试 | 无 pytest/unittest、无测试树/gutter | 全仓库 |
| 编辑 | 无 Ctrl+F/Ctrl+H 查找替换；Search Everywhere 数据源是内置样例；Find in Files 只搜内存缓冲 | `pycharm-client.ts:3369-3399,1852` |

### 1.3 直接伤「手感」的一致性瑕疵（低成本必修）
- Commit 工具窗标注 `Ctrl+K`，实际绑定 `Alt+K`（`pycharm-client.ts:1330` vs `:3539`）。
- `Tools > Profile current file` 标注 `Alt+9`，与 Version Control 的 `Alt+9` 冲突（`:2847`）。
- `Ctrl+P` 绑定的是命令面板，而非 PyCharm 的「转到文件」。
- 注：Shift+F10 运行「当前激活配置」而非当前打开文件——这与 PyCharm 一致，**不是 bug**，但 UI 需更醒目地表明当前配置。

## 2. 七条优化主线（含实现落点与工作量）

### 2.1 迁移互操作层（无感的「第一秒」）
**目标**：打开一个 PyCharm 工程，运行配置、解释器、VCS 根自动就位。

实现：
1. **解析 `.idea/`**（只读，不写坏它）：
   - `.idea/misc.xml` → 项目 SDK 名；`.idea/modules.xml` → 模块与 SDK。
   - `.idea/runConfigurations/*.xml` → 映射为内部 `normCfg`：
     - `PythonConfiguration`：`SCRIPT_NAME`→`path`、`PARAMETERS`→`args`、`WORKING_DIRECTORY`→`cwd`、`ENV`→`env`、`INTERPRETER`→解释器。
     - `DjangoServer`/`FlaskServer`/`pytest` 等先降级为「脚本 + 参数」。
   - `.idea/vcs.xml` → VCS 根（当前 Git 模块用）。
2. **迁移向导**：首次 `openFolder` 检测到 `.idea/` 时弹一次「检测到 PyCharm 项目：导入 N 个运行配置 / 解释器？」（可跳过、可回退）。
3. **读写 `launch.json`（可选但推荐）**：既然弹窗已自称镜像 launch.json，就让 `runConfigs` 真正落盘到工程内（如 `.nl/launch.json`），实现跨机、可版本化、可被 PyCharm 之外的编辑器复用。
4. **键位方案（见 2.7）** 与迁移向导合并为一次「首次启动体验」。

落点：新增 `src/langs/pycharm-import.ts`（XML 解析用轻量正则/hand-rolled，不引重依赖）+ `src/panel/server.ts` 的 `fs*`/`openFolder` 分支 + 客户端 `openFolder` 回调弹向导。
工作量：**3–5 天**（核心是 runConfigurations 字段映射与容错）。

### 2.2 Python 解释器与包管理（无感的「能不能跑」）
**目标**：用户不必「配解释器」，venv 自动生效。

实现：
1. **解释器探测优先级**：`VIRTUAL_ENV` → 工程内 `.venv`/`venv`/`env`（读 `pyvenv.cfg` 的 `home`）→ conda 环境（`CONDA_PREFIX`/`conda env list`）→ pyenv（`~/.pyenv/versions/*/bin/python`）→ 现有 manifest 兜底（`PYTHON_BIN` → knownPaths → PATH）。
2. **解释器选择器**：状态栏语言单元旁显示 `Python 3.12 (.venv)`，点击切换；选择结果持久化（按工程路径存 localStorage 或 `.nl/settings.json`）。
3. **全链路使用选定解释器**：run / debug(debugpy) / coverage / profiler / pytest 都走同一解释器路径，而不是全局 `python`。这是 A 号门槛的核心。
4. **声明生效**：给 `builtin/python@1.0.0/manifest.json` 的 `run.discovery` 补 `versionFiles`（`.python-version` plain、`pyproject.toml` 的 `requires-python`），让 substrate 的版本排序真正工作。
5. **依赖视图（P1）**：解析 `requirements.txt` / `pyproject.toml`，提供「按需安装」入口（`python -m pip install`），带输出面板。

落点：`src/langs/discover.ts`（可复用，加 venv 规则）、新增 `src/python/interpreter.ts`、`src/panel/server.ts` 的 run/debug 分支改为「解析器优先」、客户端状态栏 + Settings。
工作量：探测 + 选择器 **3–4 天**；依赖/安装 UI **+2–3 天**。

### 2.3 符号级导航与重构（无感的「手速」）
**目标**：Ctrl+B / Ctrl+Click / Alt+F7 / Shift+F6 / Alt+Enter 手感对齐。

实现：
1. **扩展 LSP 客户端方法**（`src/lsp/LspClient.ts`）：`definition`、`references`、`rename`、`prepareRename`、`documentSymbol`、`codeAction`、`signatureHelp`、`formatting`（可选 `callHierarchy`）。
2. **面板协议**：在 `src/panel/server.ts` 增加对应 `kind`（复用现有 `check/complete/hover` 的转发骨架）。
3. **前端接线**：
   - Ctrl+B / Ctrl+Click → `definition`，跳转并记入导航历史。
   - Alt+F7 → `references`，底部「Find Usages」面板（分组、可点）。
   - Shift+F6 → `rename`（符号级；替换现有项目树的文本 rename 行为，编辑器内保留 `prepareRename` 校验）。
   - Alt+Enter → `codeAction` 快速修复弹窗。
   - Ctrl+Alt+L → 优先 `formatting`，失败回退现有 `basicFormat` 启发式。
   - Ctrl+F12 → `documentSymbol` 文件结构弹窗（区别于现在「切 Structure 工具窗」）。
4. **导航栈**：Back/Forward（Ctrl+Alt+←/→）、Recent Locations、面包屑（`documentSymbol` 路径）。

落点：`src/lsp/LspClient.ts`、`src/panel/server.ts`、`src/panel/ui/pycharm-client.ts`。
工作量：**5–7 天**（导航四件套）；Quick Fix + 格式化 **+2–3 天**。

### 2.4 调试器补全（无感的「留人」）
**目标**：从「能单步」到「能查问题」。

实现：
1. **暴露已有能力**：`DapClient.scopes()/variables()` 已实现但未给 UI（`src/dap/DapClient.ts:249-260`）。新增协议消息把 `scopes`/`variables` 回传，前端做 **Variables 树 + Scopes + Watch + Evaluate(Console)**。
2. **调用栈面板**：栈帧从「文本打印」改为可点击列表，点击跳转对应文件/行（`pycharm-client.ts:2345-2347`）。
3. **控制**：补 Pause、Restart、Run to Cursor；`attach` 要么真正实现（连接 `--listen` 适配器），要么在 UI 明确标注「暂不支持」。
4. **断点增强**：条件断点、日志断点、启用/禁用、断点列表面板、持久化（`.nl/breakpoints.json` 或 localStorage）；启动时全量下发而非仅当前文件。
5. coverage/profiler 复用 2.2 的选定解释器。

落点：`src/dap/DapClient.ts`、`src/panel/server.ts`（debug 分支）、`src/panel/ui/pycharm-client.ts`（新增 Variables/Watches 视图）。
工作量：**1.5–2 周**。

### 2.5 测试运行器（无感的「日常」）
**目标**：pytest 的 gutter 绿三角、测试树、单测/类/文件粒度运行。

实现：
1. 用选定解释器执行 `python -m pytest --collect-only -q` 发现用例，`--json`/`-q` 解析结果。
2. 测试树 dock（文件→类→函数），gutter 图标，右键 Run/Debug Test。
3. 失败跳转 + 输出面板；支持 `unittest` 作为兜底。
4. 与 Run 配置打通（新增 `type: 'pytest'` 配置项）。

落点：新增 `src/python/pytest.ts`、`src/panel/server.ts`（`test*` 消息）、客户端测试工具窗。
工作量：**5–7 天**。

### 2.6 编辑体验补课（无感的「肌肉记忆」）
实现：
1. **Ctrl+F / Ctrl+H 编辑器内查找替换**：项目已 vendor CodeMirror 5，可启用 `addon/search`（或自绘）。这是最高频、最低成本的缺口之一。
2. **Find in Files 走磁盘**：把 `:1852` 的内存遍历改为 `FsService` 递归（或接 ripgrep），支持正则/大小写/整词。
3. **Search Everywhere 真索引**：
   - Files：`fsList` 递归索引（带忽略规则）。
   - Symbols：批量 `documentSymbol` 建符号索引。
   - Actions / Recent：现有 `KCOMMANDS` + 最近文件。
   - 加模糊打分与「Recently Used」排序。
4. **多光标 / 分屏 / 多编辑区 / 语义化折叠**：P2，CodeMirror 5 能力有限，需评估是否升级编辑器内核。

工作量：Ctrl+F/H **1–2 天**；Find in Files 磁盘 **1 天**；Search Everywhere 真索引 **3–4 天**。

### 2.7 设置与键位可配置 + 外围
1. **Keymap 抽象**：把 `pycharm-client.ts:3519-3543` 的硬编码 if 链抽成 `KEYMAP` 表（`action → 组合键`），提供 PyCharm / VSCode / 自定义三档，持久化。这是「无感」的关键——不同人肌肉记忆不同。
2. **Settings 扩展**：字号/字体、缩进宽度、自动保存、终端 shell、解释器、代码风格、检查器强度。
3. **修复一致性瑕疵**：Commit 的 `Ctrl+K` 标注、Profile 的 `Alt+9` 冲突、`Ctrl+P` 语义（可改为「转到文件」，命令面板另给 `Ctrl+Shift+P`）。
4. **Git 深度**（P1/P2）：diff 视图、blame、log、分支切换/合并、部分暂存。
5. **终端 PTY**（P2）：`portable-pty`/`node-pty`，解锁 vim/颜色/Ctrl+C；注意体积与原生编译。
6. **最近项目 / New Project 向导**：目前只有「最近文件」，没有「最近项目」。

工作量：Keymap **2–3 天**；Settings **2–3 天**；一致性修复 **0.5 天**；Git diff/blame **1–2 周**；PTY **3–5 天**。

## 4. 「无感迁移」验收清单（可直接当回归用例）
1. 打开一个含 `.idea/` 与 `.venv/` 的 Python 工程：解释器自动识别为 `.venv`，状态栏可见。
2. 原有 3 条 PyCharm run configuration 自动出现在配置下拉，选中后 Shift+F10 结果与 PyCharm 一致。
3. Ctrl+B / Ctrl+Click 跳到定义；Alt+F7 列出引用；Shift+F6 重命名；Alt+Enter 出现修复建议。
4. Shift+F9 调试：Variables 树、Watch、Evaluate、调用栈可点击；断点重启后仍在。
5. 测试文件 gutter 出现绿三角，单击运行单个用例并跳转失败行。
6. Ctrl+F / Ctrl+H 在编辑器内可查找替换；Ctrl+Shift+F 搜整个工程磁盘。
7. 双击 Shift 能搜到真实工程文件与符号（非样例）。
8. 切换 Keymap 为 PyCharm 后，所有前述快捷键手感一致；重启后保持。
9. 不修改、不删除用户工程内任何原有文件（`.idea` 只读；新增文件放到 `.nl/`）。
10. 冷启动 < 2s、打开 1000 行文件 < 200ms、编辑延迟 P95 < 16ms（沿用旧文性能基线）。

## 5. 轻量化与性能约束（务必守住）
- 新增依赖必须可解释：`.idea` XML 解析建议手写轻量解析，不引 XML 重型库。
- 终端 PTY、Git 图算法等重功能做成**按需加载的扩展面板**，默认不进主包。
- 当前 `dist/Nolanguage.exe` 已约 94.4 MiB；任何新依赖都要纳入体积门禁，超阈值回砍。
- 遵守「一个页面一个 IPC」（`engine_send`）与自包含 HTML 的既有契约（`verify-pycharm` 已断言）。

## 6. 一句话结论
Nolanguage 的**外壳与运行/调试骨架已经真实可用**，但要 PyCharm 用户「无感转向」，最高杠杆的不是再加面板，而是补齐三条**迁移门槛**——**解释器自动识别、`.idea` 运行配置导入、PyCharm Keymap**——以及两条**留人能力**——**符号导航四件套、真调试变量视图**。这五项（P0+P1 的前两项）完成后，才谈得上「替代品」而非「高仿外观」。
