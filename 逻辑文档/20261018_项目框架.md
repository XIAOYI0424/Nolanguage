# Nolanguage 项目框架（2026-10-18）

> 定位：TypeScript 编写的**多语言开发与执行工作台**——自研微内核（三总线 + 性能/日志脊柱）+ 面板式 IDE + 插件化语言体系；同一份引擎可跑在系统浏览器、Edge `--app` 窗口，或作为 Tauri v2 壳的 sidecar。

---

## 1. 分层总览

```
┌────────────────────────────── 表现层 ──────────────────────────────┐
│  src/panel/pycharm-ui.ts   自包含单页 IDE（HTML/CSS/JS 同文件生成）  │
│  plugins-ui / perf-ui / profile-ui / extensions-ui   独立管理页      │
└───────────────┬──────────────────────────────────┬─────────────────┘
                │ WebSocket（浏览器）              │ stdio JSON 行（Tauri）
┌───────────────▼──────────────────────────────────▼─────────────────┐
│  传输层  src/panel/Transport.ts（WsTransport / StdioTransport，可互换）│
├────────────────────────────────────────────────────────────────────┤
│  路由层  src/panel/server.ts  switch(msg.kind) → handle*(...)        │
├────────────────────────────────────────────────────────────────────┤
│  领域层  WorkspaceService（每语言一个 slot：runner / lsp / toolchain）│
│          langs/Registry → langs/RunnerFactory → runtimes/*           │
│          lsp/ dap/ profiler/ exec/ extensions/ markdown/ git/        │
├────────────────────────────────────────────────────────────────────┤
│  内核层  kernel/{CommandBus, EventBus, ServiceRegistry}              │
│          perf/PerfSpine · log/LogSpine · correlation/CorrelationBus  │
│          store/SqliteStore（SQLite 温层 + 批量 sink + 查询）          │
└────────────────────────────────────────────────────────────────────┘
```

**两种窗口宿主**

```
A. Node SEA 单文件：Nolanguage.exe ─┬─ 启动服务 + Edge --app 窗口（默认）
                                    ├─ --open-browser → 系统浏览器
                                    └─ --no-open → 仅 HTTP/WS 服务
B. Tauri v2 壳：nolanguage.exe（Rust）─spawn→ NolanguageEngine.exe --panel-stdio
                                    （同一 exe 还负责 --extension-host）
```

## 4. 内核：三总线 + 两脊柱

| 组件 | 承载 | 实现 |
|---|---|---|
| **CommandBus** | 命令注册/执行 + 中间件链（自动埋点） | `kernel/CommandBus.ts` |
| **EventBus** | `on/once/emit` 发布订阅，`observe` 供 perf 计时 | `kernel/EventBus.ts` |
| **ServiceRegistry** | 懒加载 DI、singleton/transient、激活耗时上报 | `kernel/ServiceRegistry.ts` |
| **PerfSpine** | RingBuffer 热层、LiveMetrics、Tracer、慢路径阈值、tap → SQLite | `perf/PerfSpine.ts` |
| **LogSpine** | 结构化日志 + 过滤/采样 + tap | `log/LogSpine.ts` |
| **CorrelationBus** | 统一 sessionId/traceId/git/configHash，日志与 perf 共用 | `correlation/CorrelationBus.ts` |

装配顺序（`Kernel.start()`）：`correlation.prime()` → `perf.install(kernel)` → `log.install(kernel)` → `attachStore()`。

设计要点：**内核不认识任何具体语言**。语言的一切（扩展名、语法、运行方式、LSP、调试、性能适配）都来自 manifest。

## 5. 语言插件体系

```
builtin/<id>@<ver>/manifest.json ──validate──┐
~/.nolanguage/languages/<id>@<ver>/ ─────────┤→ LanguageRegistry ──→ WorkspaceService.addSlot()
LANG_DIR / exe 内嵌解包目录 ─────────────────┘         │                     │
                                                       │              RunnerFactory.create(manifest)
                                                       │                     │
                                                       └── 每个语言一个 slot  ├→ runtimes/*（按 run.mode）
                                                        （runner/lsp/toolchain）├→ lsp/*（按 lsp.*）
                                                                              └→ dap/ profiler/（按 debug/profiler）
```

manifest 字段 → 能力的映射：

| 能力 | 字段 |
|---|---|
| 文件类型 / 新建文件 | `file.extensions`、`defaultExt`、`fileName` |
| 语法高亮 | `grammar.rules[]`（`re` + `cls`，UI 侧编译为 sticky 正则） |
| 运行 | `run.mode`、`run.requires`、`command`、`sourceExt`、`bootstrap`、`discovery`、`timeoutMs` |
| LSP / 补全 / 诊断 | `lsp.discovery/command/languageId/serverName/diagnosticsTimeoutMs/eager/bundledFallback/degradedNote` |
| 调试 | `debug.adapter/type/discovery/command/degradedNote` |
| 剖析 / 预算 | `profiler.adapter`、`lsp.memoryHint` |
| 沙箱策略 | `trust.sandbox` |

约束：代码里**没有** `switch (language)` 分支，也没有 `LanguageId` 联合类型；新增语言 = 新增一个 manifest 目录。

## 6. 端到端数据流：在 IDE 里运行 Python

```
UI 运行按钮
  └─ BRIDGE.send({kind:'run', code, language, sessionId})        pycharm-ui.ts
       ├─ 浏览器：WebSocket ──┐
       └─ 桌面壳：invoke('engine_send') ── Rust engine.rs ── stdin
                              ↓
              Transport.parseFrame → server.ts switch(msg.kind)
                              ↓
                    'run' → handleRun(key, workspace, msg, reply)
                              ↓ 先回 runStart
                    WorkspaceService.run(id, code, opts) → requireSlot(id)
                              ↓
                    slot.runner.run({code, sessionId, mode, timeoutMs, …})
                              ↓
                    ReplSessionRunner.run()   （manifest.run.mode = repl-session）
                      · 写 snippet.py + 插件 bootstrap.py
                      · 注入 NL_* 环境变量
                      · 逐行 stdout/stderr → user-code 日志 + execution.run 指标
                              ↓
              回传：runOut（流式）/ runResult（exitCode, durationMs, stdout…）
                              ↓
              异步旁路：PanelHub 广播 kind:'log' / 'metrics' 给面板页
```

**重要边界**：`src/python/PythonRunner.ts` 只被 CLI/演示路径使用（`src/python/run.ts`），IDE 走的是通用 `repl-session` 运行时。没有 `run` 段的语言（如 markdown）在 `RunnerFactory.create` 返回 `null`，槽位只提供编辑/预览。

Python 插件声明：`repl-session` + `timeoutMs: 15000` + pyright（缺省回退内置 stub）+ cProfile + debugpy。

## 7. 消除浏览器痕迹：六层防线

目标：装好的应用不能露出"这是网页"的任何迹象——右键菜单、DevTools、缩放、翻译条、脚本对话框、`<form>` 提交、地址跳转、白屏闪烁。

| 层 | 位置 | 做什么 |
|---|---|---|
| 1. 窗口配置 | `src-tauri/tauri.conf.json` | `decorations:false`（自绘标题栏）、`visible:false`（防白闪）、`devtools:false`、`zoomHotkeysEnabled:false`、`dragDropEnabled:true`、`backgroundColor:"#1E1F22"` |
| 2. WebView2 设置 | `src-tauri/src/lib.rs::harden_webview` | 关默认右键菜单、DevTools、缩放、状态栏、脚本对话框、浏览器快捷键（`ICoreWebView2Settings3`） |
| 3. CSS 硬化 | `src/panel/ui/pycharm-css.ts` | `html,body{overflow:hidden;overscroll-behavior:none;user-select:none;cursor:default}`；编辑器/输入框/`[contenteditable]`/`.selectable` 恢复文本行为；`img{-webkit-user-drag:none}`；细滚动条 |
| 4. JS 拦截 | `src/panel/ui/pycharm-client.ts` 的 `hardenWebView` IIFE | `alert/confirm/prompt` 重写（气泡 / 安全默认值）；`contextmenu`、`dragstart`、`dragover`、`drop`、`selectstart`、`dblclick`、`submit` 捕获拦截；Ctrl+wheel 缩放；F5 / Ctrl+R / Ctrl+P |
| 5. HTML 清理 | `src/panel/ui/pycharm-shell.ts` | 无 `<form>`、无 `<a href>`（一律 `<button>` + JS）、无 `<input type=file>`、无 `createObjectURL`、无 `dataTransfer.files` |
| 6. 显示时机 | `src-tauri/src/lib.rs::on_page_load` | `PageLoadEvent::Finished` → `window.show()`；`setup` 里的 1.5 s 定时器兜底 |

第 6 层刻意放在 Rust 侧：`scripts/verify-pycharm.ts` 有一条 **"every message is an engine_send invoke"** 断言，页面只允许一条 IPC 通道。页面自己调 `plugin:window|show` 会直接破坏该约束（本清单的初版方案正是如此，已改为 Rust 实现）。

### 7.1 Rust 壳的边界（`src-tauri/`）

只做五件事，**不碰协议语义**：

1. 解析并校验 sidecar 路径（拒绝解析到自身的路径，防 fork bomb）；
2. 以 `--panel-stdio` 启动 `NolanguageEngine.exe`；
3. 按 `\n` 切行，`serde_json` 仅校验合法性，然后原样 `emit('engine_message')`；
4. 唯一 IPC 命令 `engine_send`（写一行 JSON 到 sidecar stdin）；
5. 单实例插件、WebView2 硬化、系统文件对话框、页面加载完成时显示窗口、stderr 转发与退出事件。

传输等价性由 `scripts/verify-transport.ts` 验证：WebSocket 与 stdio 可互换。

## 8. 构建与产物

| 目标 | 命令 | 产物 |
|---|---|---|
| 引擎单文件 | `npm run build:exe` | `dist/Nolanguage.exe`（Node SEA，PE Subsystem 2 = GUI） |
| 前端单页 | `npm run build:frontend` | `frontend/dist/index.html`（自包含） |
| 安装包（Node SEA 形态） | `npm run build:setup` | `installer/Nolanguage-Setup.exe`（22.2 MiB，中文 NSIS 向导） |
| Tauri 壳 + 安装包 | `.\node_modules\.bin\tauri.cmd build --bundles nsis` | `src-tauri/target/release/bundle/nsis/*.exe`（23.7 MiB） |
| 开发运行 | `npm run panel` / `npm run ide` | 本地 HTTP + WebSocket（默认 7310） |

打包链路：`build-exe.mjs` = esbuild 打成 CJS → 内嵌 `pyrightServer.py`、示例扩展、`builtin/` 到 `globalThis.__NOLANGUAGE_EMBEDDED__` → Node SEA blob → postject 注入 → PE 子系统改 GUI。

运行时：打包版把内嵌 `builtin/` 释放到 `%TEMP%\nolanguage-embedded\builtin`，用户插件在 `~/.nolanguage/languages`。

### 8.1 卸载路径

| 安装方式 | 卸载器 | 来源 | 注册表指向 |
|---|---|---|---|
| NSIS 包（SEA 形态，`npm run build:setup`） | `uninstall.exe` | NSIS `WriteUninstaller` 自动生成 | 安装时写入 |
| NSIS 包（Tauri 形态，`tauri build --bundles nsis`） | `uninstall.exe` | NSIS 自动生成 | 安装时写入 |
| `setup.ps1` 直装 | `uninstall.exe` | Rust 独立二进制（`installer/uninstaller/`） | `setup.ps1` 写入 |
| SEA 直接分发（复制 exe 运行） | 无 | — | 手动删除 |

**`installer/uninstaller/` 的定位**：仅服务于 `setup.ps1` 这条零依赖路径。NSIS 两条路径不依赖它，但它的存在让"没有 NSIS 也要有正常卸载体验"成立。

### 8.2 两套 NSIS 安装包的关系

| 维度 | 自研 NSIS（`npm run build:setup`） | Tauri NSIS（`tauri build --bundles nsis`） |
|---|---|---|
| 引擎形态 | Node SEA 单文件 | Tauri Rust 壳 + Node sidecar |
| 向导语言 | 中文 | 英文（Tauri 默认模板） |
| 安装路径 | `%LOCALAPPDATA%\Programs\Nolanguage` | `%LOCALAPPDATA%\Nolanguage` |
| 卸载器 | NSIS 自带 | NSIS 自带 |
| 适用场景 | 中文用户、SEA 形态 | Tauri 形态、英文用户 |
| 维护方式 | 独立维护（`installer/Nolanguage.nsi`） | 随 Tauri 版本升级 |

两者独立维护，安装路径不同，**可以并存**——这是设计选择，不是缺陷。

### 8.3 引擎镜像的单一真源

```
dist/Nolanguage.exe                                   ← 唯一真源（build:exe 产出）
      │  node scripts/sync-sidecar.mjs   (sha256 比对，差异才复制)
      ▼
src-tauri/binaries/NolanguageEngine-<triple>.exe       ← 构建产物，不手工编辑
```

- `package.json` 的 `postbuild:exe` 钩子在 `npm run build:exe` 成功后自动同步（删掉 sidecar 再构建会被自动恢复，已实测）；
- `tauri.conf.json` 的 `beforeBuildCommand` 在构建前端之后自动跑同步，所以 `tauri build` 不可能再打包出"壳新引擎旧"的安装包；
- `npm run verify:sidecar`（`sync-sidecar.mjs --check`）只校验不写入，差异时退出码 1，可直接放进 CI；
- 同步脚本同时负责 triple 后缀：`externalBin` 写的是 `binaries/NolanguageEngine`，磁盘上的文件必须带 `-<triple>`，打包器会剥掉它。

## 10. 设计约束（读代码时最该记住的几条）

1. **Rust 不解析协议**：任何 `kind` 相关逻辑出现在 `src-tauri/` 都算越界。
2. **没有语言分支**：语言能力只来自 manifest；新增语言不改引擎代码。
3. **双入口，职责分明**：
   - **TS 入口**：`src/desktop/main.ts` 的 argv 分派（`--extension-host` / `--panel-stdio` / 默认），是引擎的唯一入口；重复调用 `main()` 会因端口占用而失败。
   - **Rust 入口**：`src-tauri/src/main.rs` → `lib.rs::run()`，只负责建窗、装插件、spawn sidecar，不直接跑引擎。
   - **两者关系**：Rust 入口 → 启动 sidecar → sidecar 跑 TS 入口；用户永远只启动一个 exe，TS 引擎作为子进程运行。
4. **IDE 与 CLI 两条执行路径**：IDE = `repl-session`；`PythonRunner`/`GoRunner`/`JsRunner` 属 CLI/演示路径。
5. **日志与协议分离**：sidecar 的 stdout 只跑协议行，日志走 stderr / logger。
6. **打包后无控制台**：SEA 的 PE 子系统在构建时改为 GUI，Tauri sidecar 复用同一镜像。
7. **浏览器原生 UI 不得出现**：Rust 层 WebView2 设置是根治；前端三层（`tauri.conf.json` 窗口配置、CSS 全局硬化、JS 事件拦截）是双保险。窗口显示由 Rust 的 `on_page_load` 负责，页面不得为此新增 IPC。
8. **旧 runner 是活文档**：`src/python/` / `src/go/` / `src/js/` 不再被 IDE 调用，但保留作为"插件化前后行为等价"的证明。删掉它们等于删掉回归基线。
9. **引擎镜像只有一个真源**：`dist/Nolanguage.exe` 是唯一真源，`src-tauri/binaries/NolanguageEngine-<triple>.exe` 由 `scripts/sync-sidecar.mjs` 生成（`tauri build` 前自动执行）。不要手工复制——那正是"壳新引擎旧"的成因（见 §8.3）。

## 11. 当前完成度与已知限制

已完成：内核三总线与双脊柱、面板 IDE（编辑/运行/检查/补全）、LSP 闭环、Go/JS/Markdown 插件、扩展宿主、沙箱执行平面、SQLite 温层与 baseline、Tauri 壳与 sidecar、Windows 安装器与无控制台打包。

已知限制：

- 两套安装包安装路径不同（`Programs\Nolanguage` 与 `Nolanguage`），**可并存**，这是设计而非缺陷（见 §8.2）；
