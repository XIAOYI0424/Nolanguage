## 0. 总体结论

**这是一个架构质量明显高于功能完成度的项目。** 它的内核设计（三总线 + 自监测 + manifest 插件化 + 零运行时依赖）是真正成熟、且在这个体量里罕见的；但它的**语言智能、测试、环境与生态**还停留在「能用」而非「好用」。

一句话：**引擎（8 分）强于 IDE（6 分），工程纪律（8.5 分）强于功能覆盖（5.5 分）。**

| 维度 | 评分 | 判断 |
|---|---:|---|
| 架构设计 | 8.5 / 10 | manifest 驱动、语言无关、三层可观测；几乎无语言硬编码 |
| 工程纪律 | 8.5 / 10 | 35 套件 / 1639 断言 + CI + 类型检查；但单元测试薄、有门禁空洞 |
| 编辑器体验 | 6.5 / 10 | CM5 + 补全/hover/内联诊断/断点/查找替换齐备；**无符号导航** |
| 调试能力 | 7.5 / 10 | DAP 完整度高（含 attach、watch、求值、构建前置）；**无高级断点** |
| 语言智能 | 4 / 10 | 仅 completion / hover / publishDiagnostics |
| 生态与交付 | 5 / 10 | Tauri 已搁置（依赖系统 Edge）、市场为 placeholder、AI 为死入口 |
| **综合** | **6.8 / 10** | 「高完成度的内核 + 中等完成度的 IDE」 |

## 2. 架构与规模

### 2.1 分层

| 层 | 位置 | 职责 |
|---|---|---|
| 内核 | `src/kernel`、`perf`、`log`、`store`、`correlation` | CommandBus/EventBus/ServiceRegistry + 自动埋点 + SQLite 暖层 + JSONL 冷归档 + traceId 关联 |
| 语言与运行时 | `src/langs`、`runtimes`、`lsp`、`dap`、`profiler` | manifest 插件、五种运行模式、LSP/DAP 客户端、覆盖率、profiler |
| 面板 | `src/panel` | WS/HTTP/stdio 服务端、`WorkspaceService`、`FsService`、IDE UI 装配 |
| 客户端 | `src/panel/ui/client/*.js`（8 片，约 4,423 行） | 以 `?raw` 文本按序拼接，共享同一 IIFE |
| 桌面 | `src/desktop`（在用）、`src-tauri`（已搁置） | Edge `--app` 宿主 / Tauri 壳 |
| 扩展 | `src/extensions`、`mcp` | 独立 extension host 子进程；stdio MCP |

### 2.2 规模

- `src/panel/server.ts` **1,685 行**、`WorkspaceService.ts` **1,229 行**、`langs/Registry.ts` **714 行**——业务仍高度集中在少数大文件。
- 客户端 8 片合计 **4,423 行 / 208 KB**；`pycharm-css.ts` 632 行。
- 产物：`dist/Nolanguage.exe` **94.9 MiB**（Node SEA + 内嵌 builtin），安装包 **22.7 MiB**，单页 HTML **~924 KB**（自包含、无 CDN）。

## 3. 能力矩阵

### 3.1 已实现且真实可用

- **运行**：五种语言无关模式 `template` / `repl-session` / `directory-session` / `inline-vm` / `script-host`（`src/runtimes/index.ts:15-33`）。
- **调试**：manifest 决定 adapter/discovery/launch 模板/preLaunch/attach；UI 有 Continue/Pause/Step×3/Stop、Frames、Variables（可递归展开）、Watches、Evaluate 控制台、当前执行行标记、源码跳转、断点持久化、attach。
- **编辑器**：CM5、多语言高亮、自动缩进/括号闭合、L1+L2 补全、hover、内联诊断、Problems 跳转、查找替换、断点（CM gutter + textarea 回退）。
- **可观测**：Performance（p50/p95/p99 + sparkline）、Logs（级别过滤）、Flame Graph（内核 V8 采样）、覆盖率（Python 行覆盖）、Profiler（cProfile / pprof）。
- **项目与文件**：FsService（含路径逃逸防护、4MB 限制）、多标签、最近文件、真实 CRUD。
- **插件**：语言插件分层注册表、安装/启停/卸载/迁移/依赖检查；扩展 host 子进程。
- **解释器**：真实探测 + UI 选择 + pin。

### 3.2 部分可用（边界会失效）

| 项 | 边界 |
|---|---|
| Find in Files | 只扫已加载 `BUFFERS`，非全工作区（`40-docks.js:137-166`） |
| Search Everywhere | files 来自内嵌 `FILES`；symbols 是硬编码 sample（`70-shell.js:66-101`） |
| Structure | 仅 Python `def/class` 正则（`30-panels.js:746-753`） |
| Reformat | 本地文本卫生，非 LSP formatting / black / gofmt |
| Terminal | 管道式，非 PTY；**且 cwd 用 `process.cwd()` 而非 `FsService.root`** |
| MCP | 协议完整，但 UI 固定传 `{}`，带参数的工具用不了 |
| Commit | 仅 `add -u` + `commit`，不提交 untracked |
| i18n | 有机制与 zh-CN bundle，但大量运行时文案硬编码英文 |

### 3.3 缺失

1. **LSP 导航与重构**：无 `definition / references / rename / documentSymbol / workspaceSymbol / codeAction / formatting / signatureHelp / semanticTokens`。这是目前**最大的能力短板**——直接决定大项目里能不能高效改代码。
2. **测试运行器**：无 pytest/unittest/测试树/用例发现/失败定位（底层 manifest 可声明 `test` step，但 IDE 侧没有）。
3. **环境创建与包管理**：能发现现有 venv/conda，不能创建/删除/激活；无 pip/poetry/npm/go mod 图形化管理。
4. **高级断点**：无条件断点、日志点、异常断点、hit condition、setVariable、threads UI、restart。
5. **高级 Git**：无 diff、hunk stage、history、branch、remote、stash、冲突解决。
6. **AI Assistant**：死入口（仅渲染输入框，无 listener、无后端）。
7. **Database / Docker / Remote / HTTP Client**：明确不在范围内。

## 5. 性能与体积

- 有**长期 baseline 机制**（按 git commit 存快照、10%/0.5 双阈值比较、越高越好指标识别，`src/perf/BaselineStore.ts:65-82`）。

- **但**：CI 未对真实冷启动耗时、内存、95 MiB exe 体积设硬 SLO；`memoryHint` 对 LSP 是估算而非 RSS 实测（`WorkspaceService.ts:1128-1148` 自己也承认）。

## 6. 风险与问题（按优先级）

### P0 —— 已核实的代码缺陷

1. **`case 'profileResult'` 重复，后半段不可达**
   `50-runtime.js:610-612` 已 `break`；`:781-786` 的 localStorage 暂存与 toast **永远不会执行**（profile 结果持久化/提示被静默跳过）。

2. **DAP 断点设置在 `configurationDone` 之后**
   `server.ts:1516-1520`：`await dap.start()`（内部完成 launch → initialized → configurationDone）**之后**才 `setBreakpoints`。DAP 惯例是在 configurationDone 之前下发；当 `stopOnEntry=false` 时程序可能已越过断点行甚至结束。

3. **终端 cwd 与工作区不一致**
   `server.ts:1134-1137` 用 `process.cwd()`，而 UI 文案称"项目根目录"；打开别的工程后终端实际仍在启动目录。

### P1 —— 架构与一致性风险

4. **客户端拆分消除了模板事故，但没消除耦合**：8 片仍共享一个 IIFE、依赖声明顺序、跨文件可变全局；无模块边界、无类型检查。
5. **若干 UI 文案强于实际能力**（Find in Files 只查 buffer、symbols 是 sample、Structure 只认 Python、终端 cwd 不符）——构成"看起来像 IDE，语义边界未诚实显露"的体验风险。
6. **双桌面路线维护成本**：Tauri 已正式搁置（`docs/Tauri搁置说明.md`：本机 WebView2 运行时 143 损坏且无管理员权限无法升级，20 行 wry 探针同样加载不完 → 判定为环境问题），但 `src-tauri` 代码与 94.9 MiB sidecar 仍在，主产品依赖系统 Edge `--app`。
7. **文档漂移**：`docs/系统评估_20261027.md` 仍写"单模板 4200 行、CI 不在仓库"（均已变）；`添加新语言指南.md:6` 引用的 `语言插件化设计.md` 已不存在（断链）。

### P2

8. Keymap 硬编码，无可编辑方案/冲突检测/导入 PyCharm keymap。
9. 插件 catalog 默认服务 `https://plugins.nolanguage.dev/index.json` 源码自称 placeholder。
10. LSP 仍只有 completion/hover/diagnostics 三方法。

## 8. 结语

Nolanguage 最值得肯定的不是功能多，而是**每一处能力都带着可执行的断言**，以及**"语言无关"这件事是真的做到了**（调试侧已无语言分支，运行侧五种模式覆盖，解释器/迁移/插件全是声明式）。

它当下最该补的也不是再加面板，而是三件事：**修掉 3 个静默缺陷、补上符号级导航、让文档与代码同步**——这三件做完，它会从一个"内核很强、IDE 一般"的项目，变成"内核很强、IDE 也够用"的项目。
