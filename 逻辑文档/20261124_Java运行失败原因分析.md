# Java 为什么无法运行（NeroSama 面板协议测试）

> 日期：2026-11-24 · 依据：`D:\Nolanguage` 0.7.24-workspace 的实际运行链路 + 本次测试帧数据
>
> 结论先说：**不是 Java 工具链坏了，也不是 NeroSama 的代码坏了**。是 Nolanguage 的 Java 运行方式（"把一个源码文件丢给 JDK 直接跑"）与这个项目的真实形态（Gradle 10 个模块的 Spring Boot Web 服务）不是同一种运行方式。同一个通道跑最小 `Main` 类成功（`exitCode 0`，输出 `java-run-ok`），已经证明通道本身正常。

## 一、直接原因：public 类名与临时文件名不一致

报错原文（GBK 被按 UTF-8 解码，已还原）：

```
错误: 源文件的路径末尾的字符串 com.nero.vtuber.app 不匹配:
C:\Users\15936\AppData\Local\Temp\nolanguage-java-morjNm\main.java
```

链路是固定的，三步都能在代码里指出来：

1. `src/runtimes/template.ts:70`：`TemplateRunner.run()` 把前端送来的源码写到临时目录，**文件名写死为 `main.java`**：
   ```ts
   const file = await materialiseSource(opts, session.dir, `main${ext}`);
   ```
   `:74` 再把 `{file}` 替换成这个路径。
2. `builtin/java@1.0.0/manifest.json:343-347`：Java 的运行步骤只有一条：
   ```json
   { "role": "run", "cmd": "\"{toolchain}\" \"{file}\"" }
   ```
   也就是 JDK 11+ 的 **source-file 模式**：`java main.java`，内存里编译后立即执行。
3. source-file 模式的硬规则：**public 类的名字必须与源文件名一致**。`Application.java` 里是 `public final class Application`（`vtuber/java/app/src/main/java/com/nero/vtuber/app/Application.java:26`），文件却叫 `main.java`，JDK 因此在编译前直接拒绝，退出码 1，耗时 234ms，还没轮到执行任何项目逻辑。

## 二、第二层原因：即使把类名改成 `Main` 也跑不起来

source-file 模式只把当前这一个文件交给编译器，classpath 里没有别的依赖。而 `Application.java` 的 imports 包含：

- `org.springframework.boot.SpringApplication` / `@SpringBootApplication`（Spring Boot 3.3.5）
- `com.nero.vtuber.core.*`、`com.nero.vtuber.app.*`（本项目其他模块）

`vtuber/java/app/build.gradle` 声明了 8 个 `implementation project(...)` 和 Spring Boot Web，`settings.gradle` 包含 10 个子模块。所以要跑它至少需要：

```
-classpath <bootJar 或 全部子模块 class + Spring 依赖 jar>
```

而清单里的 `"{toolchain}" "{file}"` 没有 `-cp`，`{file}` 之外也没有任何注入 classpath 的占位符。改名后只会把错误从"类名不匹配"推进到"程序包 org.springframework... 不存在 / 找不到符号"。

## 三、第三层原因：它是常驻 Web 服务，不是一次性程序

`Application.main()` 第一行就是 `SpringApplication.run(Application.class, args)`，`app/build.gradle` 也把 `bootJar.mainClass` 设成 `com.nero.vtuber.app.Application`。这是一个会启动内嵌 Web 服务器并保持运行的程序。

Nolanguage 的 `template` 运行时是按"写源码 → 跑命令 → 等退出码"设计的（`src/runtimes/template.ts:64-87`），没有项目级入口类、classpath、工作目录和运行后停止的配置入口。即使前两层都解决，"跑完拿 exitCode"这个模型也不匹配常驻服务。

## 四、为什么 Python 能跑

两者用的运行时根本不同：

| | Python | Java |
|---|---|---|
| 运行时 | `repl-session`（会话型，按代码块执行） | `template`（源码落盘 + 命令模板） |
| 工具链 | 项目 `.venv\Scripts\python.exe`，Python 3.14.2 | `java` 25.0.2（PATH 发现） |
| 同名约束 | 无 | 文件名必须等于 public 类名 |
| 本次结果 | `utils.py` 输出 `13`，exit 0，89ms | 最小 `Main` 输出 `java-run-ok`；真实 `Application.java` exit 1 |

## 五、正确的运行方式（本次没有执行，原因是"不改项目 + 不直接调命令"）

项目自己给出的入口是 Gradle / Spring Boot：

```text
D:\15936\Documents\NeroSama\vtuber\java\app\build\libs\app-0.1.0-SNAPSHOT.jar
bootJar.mainClass = com.nero.vtuber.app.Application
```

对应的运行形态是 `java -jar <fat jar>` 或 `gradlew :app:bootRun`，而不是 `java main.java`。

要让 IDE 能跑，可选路径有三条（都要改 IDE 侧，不动 NeroSama）：

1. 给 Java 清单/运行配置增加**项目模式**：声明入口类、classpath（fat jar 或 Gradle 输出目录）、工作目录，由 `runConfigs` 带入 `run` 消息。
2. 在 IDE 的 `run` 通道里支持"运行项目已有产物"（fat jar），而不是只支持"把源码写到临时文件再跑"。
3. 最低成本：加一条 `java -jar "{project}/.../app-...jar"` 的模板步骤，但仍需解决常驻服务的停止语义。

## 六、附带的两个观察

- 错误文本里中文全是乱码：子进程 stderr 是 GBK，面板按 UTF-8 解码（`runOut` 帧原样转发），不影响执行但影响排错。
- 首轮探针断连触发引擎 `EPIPE` 未捕获而退出；这是写帧路径缺少降级处理，与本节的 Java 失败无关，但会让排错时面板突然消失。
