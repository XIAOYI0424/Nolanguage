## 一、前置事实（都已核对，含三个待确认问题的答案）

### 1.1 `manifest.lsp.supportsDynamicConfig` 不存在，且不建议新增

全仓零命中。切换走"重建"是刻意的：

```386:393:src/panel/WorkspaceService.ts
   * The slot is **rebuilt**, not patched: the runner and the language server are
   * both assembled from the binary at construction time, so a half-updated slot
   * would report the new interpreter while still executing the old one — the
   * exact failure the picker exists to prevent.
```

只推送 LSP 而不重建 runner，就会出现"状态栏是新解释器、执行的是旧的"。**不加这个字段。**

### 1.2 slot 没有 `restart()`，但 `WorkspaceService` 有等价能力

| 方法 | 行 | 语义 |
|---|---|---|
| `setToolchain(id, bin)` | 394 | 校验路径 → `removeSlot` → `addSlot` → `ensureLsp`，**runner + LSP 一起重建** |
| `restartLanguageServer(id)` | 443 | `releaseLsp` + `ensureLsp`，装包后让服务器重读导入图 |

计划里写的 `waitForFirstCompletion()` 也不存在；现有原语是 `waitForUpgrade(slot)`（takeover 等待）。

### 1.3 `generate()` 已接受 `targetDir`

```96:116:src/scaffold/registry.ts
  generate(language, id, submitted, targetDir, opts: { allowNonEmpty?: boolean } = {})
      ...
    if (!isAbsolute(targetDir)) throw new Error('目标目录必须是绝对路径');
    if (existsSync(dir) && !opts.allowNonEmpty) { … 非空拒绝 … }
```

**17 套模板零改动。**

### 1.4 `run.interpreters` 是现有 manifest 字段

python 插件已声明 `envDirs(.venv/venv/env/.env)`、`marker(pyvenv.cfg)`、
`versionDirs(.pyenv/*)`、`envListFile(.conda/environments.txt)`、`sdkPrefix`；
`interpreters.ts` 的 `INTERPRETER_SPECS`（56 行起）只是"插件没声明时"的兜底表。
→ 要加的是 `create`，**不要新开 `environments` 顶层键**（同一概念两套声明，门禁无法保证一致）。

### 1.5 vendor 里没有折叠与多光标插件

`src/vendor/codemirror/` 实际只有：

```
addon/edit/closebrackets.js   addon/edit/matchbrackets.js
addon/selection/active-line.js   addon/hint/show-hint.js (+css)
```

缺 `addon/fold/{foldcode,foldgutter,brace-fold}.js`、`addon/fold/foldgutter.css`、
`addon/selection/multiple.js`。而装配是**固定 import 列表**（`ui/codemirror-assets.ts` 22–44 行），
新文件必须手动加 import 并保证注入顺序。

### 1.6 LSP 新能力要走四段链，不是"收到就渲染"

`LspClient` 没有公开的通用 `request()`，每个能力是具名方法（`definition` / `hover` /
`completion` / `formatting` …）。新增 `foldingRange` 或 `inlayHint` 需要：
`LspClient.<method>` → `lsp/navigation.ts` normalize → `panel/server.ts` 新 kind →
`50-runtime.js` 处理 → `20-editor.js` 渲染，并受 `ServerCapabilities` 门控。

### 1.7 唯一 spawn 点是 `handlers/run.ts`

`server.ts` 只分派 76 种 `kind`；终端、运行、调试、脚本都在 `panel/handlers/run.ts`
（620 行，含 killTree、超时、4 MiB 输出上限）。**任何新的进程执行都加在这里。**

### 1.8 现有文件操作能力（子项目与恢复都要用）

`FsService` 已有 `write`(320) / `create`(343) / `rename`(364) / `remove`(399)，且以
`root` 为界做校验；`util/appData.ts` 的 `appDataDir()` 是应用态根
（`%LOCALAPPDATA%\Nolanguage`，`NOLANGUAGE_DATA` 可覆盖）。

## 二、八项逐条设计（按实施顺序编号）

### P0-1 · 崩溃恢复（自动草稿）

**现状**：无。全仓 `autosave` 只出现在 `panel/demo-commands.ts` 的演示日志里。

**为什么不放项目内 `.tmp/`**：那会污染用户工作区，且 `.tmp/` 只在仓库里被 gitignore；
用户项目没有这个约定。草稿是**应用态**，放 `appDataDir()/autosave/`。

| 落点 | 改动 |
|---|---|
| `10-state.js` | `BUFFERS[path].content` 更新且 `dirty` 时，debounce 2s 发 `draftSave {path, content}` |
| `panel/handlers/fs.ts` | 新增 `draftSave` / `draftList` / `draftDrop`；写入 `<appData>/autosave/<sha1(absPath)>.json` + `index.json`（记录 absPath / mtime / bytes） |
| `70-shell.js` boot | `draftList` → 与磁盘内容比对 → 一个对话框列"未保存的草稿"，恢复进 `BUFFERS`（**标 dirty，不写盘**） |
| 保存 ACK 后 | `draftDrop {path}`，与现有"ACK 才清 dirty"同一条路径 |

**不变量**：草稿不是保存的替代，绝不自动落盘；磁盘内容在草稿之后被改过时**不覆盖**，
提供"另存为 `<name>.recovered`"而不是猜。

**门禁**：写入草稿 → 重启面板 → 断言草案内容回到缓冲区且标签是 dirty；再断言磁盘文件未变。
注入验证：去掉 boot 的比对分支，门禁必须红。

**成本**：0.5–1d。

### ~~P0-2~~ · 在工作区内新建子项目 —— **已实现，删除**

**复核结论（2026-11-18）**：向导早就是"在打开的工作区里生成一个子目录"：

```js
// 69-wizard.js:243  Target = workspace root + the template's suggested subdirectory.
function wizTargetDir(t) {
  if (!WIZ.dir) {
    var base = String(WIZ.root || '').replace(/[\\/]+$/, '');
    var sub = '';
    if (t && t.suggestedDir) { …把 {{name}} 之类占位符替换成表单值… }
    WIZ.dir = base + (sub ? '/' + sub : '');
  }
  return WIZ.dir;
}
```

`templatesGenerate` 发的是这个绝对路径，`scaffold/registry.ts` 再拦非空目录、盘根与非绝对路径
（配「允许非空」复选框）。所以这一项不需要任何代码；下表保留作废记录，避免下次又当成缺口。

| 落点 | 改动 |
|---|---|
| `69-wizard.js` | 已有工作区时多一个模式：`targetDir = join(root, sub)`；子目录名校验（非空、无 `/ \ : * ? " < > |`、不以 `.` 开头、不存在或为空） |
| `scaffold/registry.ts` | **不改** |
| manifest | **不加 `multiRoot` 字段**：`generate` 已经用"非空拒绝 + 盘根拒绝"表达了全部约束，再加一个没人读的开关就是制造第二个真相（R7 纪律） |

**范围必须说清**：这是"在工作区里生成一个子目录"，**不是多根工作区**。
`WorkspaceService` 只有单一 `rootDir` / 单套 slot / 单 LSP 根；真多根要"每根一套 slot +
每根 LSP"，是另一个量级（约 5–8d）。所以 v1 门禁里"两个根各自 LSP 不互串"这一条
**当前实现做不到，删掉**；改成"子项目文件出现在项目树、可编辑、单根 LSP 正常工作"。

**成本**：0.5d。

### ~~P1-3~~ · 多光标 —— **CM5 做不到，阻塞（需 CM6）**

**复核结论（2026-11-18，已下载官方 `codemirror@5.65.21` 包核对）**：CM5 **没有多选区**。
npm 包里 `addon/selection/` 只有三个文件：

```
addon/selection/active-line.js       已 vendor
addon/selection/mark-selection.js
addon/selection/selection-pointer.js
```

计划里写的 `addon/selection/multiple.js` **根本不存在**（这也是 cdnjs / unpkg 对该路径返回 404 的
原因）。多选区是 **CodeMirror 6** 的能力（`EditorState` 的 `ranges`）。要在 CM5 上做，等于重写核心
的选区/输入/撤销模型——不是接线，是一个独立项目。

因此：**不做**。真正的替代路径是迁移到 CM6（ESM 多包，需要打包器，与"零构建、单文件自包含"
的两条不变量直接冲突），要么接受 CM5 的单光标。

> 顺带修正本方案早先的说法：vendor 里缺的不是"一个 addon"，而是**这类能力在 CM5 里不存在**。
> 提前核对这一点，省掉了一天"接线"和一次错误的门禁设计。

改文档跑 `npm run verify:docs`。

## 四、门禁设计（每条都要能红）

| 门禁 | 断言 | 注入验证（必须红） |
|---|---|---|
| 崩溃恢复 | 有草稿 → 重启 → 内容回到 dirty 缓冲；磁盘未变 | 去掉 boot 比对分支 |
| 子项目 | 工作区内生成子目录，树里出现、可打开、单根 LSP 仍工作 | 传相对路径给 `generate`（应被拒） |
| 多光标 | 命令已注册 + 文档两个选区（jsdom）；真编辑（live） | 移除 addon import |
| 折叠 | 范围数与行映射正确（jsdom）；折叠后可见行减少（live） | 移除 `foldGutter` 初始化 / 移除 debounce 外的范围重设 |
| 环境创建 | 创建后 `pyvenv.cfg` 存在；切换后 `toolchains()[id]` 变且发生一次 LSP 重启 | 注释掉 `removeSlot`（runner 不重建）→ 必须红 |
| editable | `pip show -f` 指向源码路径 | 把模板换成 `install`（非 editable）→ 必须红 |
| Inlay | 支持时有 hint 且位置正确；不支持时零渲染零报错 | 去掉能力门（对 marksman 触发） |
| 测试运行器 | 单节点只跑一个用例；失败进 Problems | 去掉 `-run` 过滤（会跑全部） |

**不要写"依赖补全刷新"这类断言**：它取决于 pyright 缓存失效时机，会抖。

## 五、七条不变量逐条对照

| # | 不变量 | 本方案 | 具体结论 |

| 1 | 引擎零语言分支 | ✅ | 环境命令、测试命令、安装模板全部 manifest 声明；引擎只认占位符白名单 |

## 六、明确不做（以及为什么）

| 项 | 原因 |
|---|---|
| `manifest.lsp.supportsDynamicConfig` | 推送式切换会让 runner 与 LSP 脱节，`setToolchain` 的重建语义才是安全的 |
| `scaffold.multiRoot.supported` | `generate` 已用"非空拒绝 + 盘根拒绝"表达约束；再加开关就是没人读的第三个真相 |
| `environments` 顶层 manifest 键 | `run.interpreters` 已经在做同一件事 |
| 真多根工作区（每根一套 slot/LSP） | 需要改 `WorkspaceService` 的 root 模型，5–8d，且现有 53 套件里多处假设单根 |
| PTY 终端 / 非 stdio MCP / 非 Python 覆盖率 | 各自的实现前提都不在（Windows 无 pty、MCP SSE 未做、只有 `trace` 提供解释器级行覆盖） |
