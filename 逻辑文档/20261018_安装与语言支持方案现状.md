# Nolanguage 安装与语言支持方案现状（2026-10-18）

> 范围：桌面分发形态（两套安装包）、安装器实现、无控制台/无翻译弹窗的处理、语言插件体系，以及本轮实测结论。
> 结论先行：**两套安装包都能装、能启动、无黑框、无翻译提示；Python 语言已内置、无需安装命令。**

## 2. 两种运行形态

```
形态 A（NSIS 包，Node SEA 单文件）
  Nolanguage.exe ──┬─ 无参数          → 自带服务 + Edge --app 窗口（桌面形态）
                   ├─ --open-browser  → 自带服务 + 系统默认浏览器
                   └─ --no-open       → 只起 HTTP/WebSocket 服务（CI / 无头）

形态 B（Tauri 包）
  nolanguage.exe（Rust 壳，4.7 MB）
      └─ spawn ─→ NolanguageEngine.exe --panel-stdio
                    （stdio 上跑 JSON 行协议；同一 exe 还负责 --extension-host）
```

两种形态共用同一份引擎代码与同一套语言插件；差异只在"窗口由谁提供"。

## 3. 安装器方案（`installer/Nolanguage.nsi`）

MUI2 四页向导，简体中文：

1. **欢迎页** —— 产品/版本
2. **选择安装位置** —— 默认 `%LOCALAPPDATA%\Programs\Nolanguage`，可浏览/输入；`InstallDirRegKey` 记住上次目录
3. **安装进度** —— 进度条 + 实时日志（解压 / 写快捷方式 / 写注册表）
4. **完成页** —— 可勾选"运行 Nolanguage (Desktop)"

安装动作：

- `nsExec::ExecToLog taskkill /IM Nolanguage.exe /F /T`（隐藏窗口，静默结束旧实例）
- `File` 解压 `Nolanguage.exe` → `WriteUninstaller` → 开始菜单 3 项 + 桌面快捷方式
- 注册表：`DisplayName / DisplayIcon / DisplayVersion / Publisher / InstallLocation / UninstallString / QuietUninstallString / EstimatedSize / NoModify / NoRepair`
- 卸载：结束进程 → 删程序与快捷方式 → `RMDir`（**仅空目录**，保留 `.nolanguage` 用户数据）→ 删注册表项

构建入口：

```bash
npm run build:exe        # → dist/Nolanguage.exe（GUI 子系统）
npm run build:setup      # → installer/Nolanguage-Setup.exe
```

`installer/build-setup.mjs` 的 `makensis` 查找链：`%NSIS_MAKENSIS%` → `%LOCALAPPDATA%\tauri\NSIS` → `PATH` → `C:\Program Files (x86)\NSIS`；脚本以 `-INPUTCHARSET UTF8` 编译（保证中文界面不乱码）。

静默安装：`Nolanguage-Setup.exe /S /D=<目录>`（`/D` 必须是最后一个参数）。

## 4. 本轮的关键修复

### 4.1 黑框（控制台窗口）——根因在 exe 本身，不在安装器

Node SEA 默认复制 `node.exe` 的 **console** 子系统，双击必然分配控制台窗口。安装器（NSIS）与 Tauri 壳本来就是 GUI 程序，不产生黑框。

修复：`scripts/build-exe.mjs` 增加 `setGuiSubsystem()`，构建后把 PE OptionalHeader 的 `Subsystem` 从 3 改为 2：

```js
const peOffset = image.readUInt32LE(0x3c);
const subsystemOffset = peOffset + 24 + 68;
image.writeUInt16LE(2, subsystemOffset);
```

副作用：stdio 句柄无效，日志不再出现在控制台；服务与 UI 不受影响（实测 HTTP 200）。Tauri 的 sidecar 复用同一份 exe，因此 sidecar 也不再弹框。

### 4.2 浏览器翻译弹窗

UI 是英文（`<html lang="en">`），中文系统上 Chromium 每次启动都会提示翻译。三处一起处理：

| 形态 | 位置 | 手段 |
|---|---|---|
| 系统浏览器（Web） | `src/panel/pycharm-ui.ts` | `<meta name="google" content="notranslate">` |
| Edge `--app` 窗口 | `src/desktop/WebViewHost.ts` | `--disable-features=...,Translate,TranslateUI` |
| Tauri WebView2 | `src-tauri/tauri.conf.json` | `additionalBrowserArgs` 追加 `Translate,TranslateUI`（保留 Tauri 默认三项） |

### 4.3 sidecar 查找与命名（Tauri 形态）

- `externalBin: binaries/NolanguageEngine` → 构建时文件必须带 triple 后缀；安装包会剥离 triple。
- `engine.rs::sidecar_path()` 依次尝试 `NolanguageEngine.exe` 与 `NolanguageEngine-<triple>.exe`，并对解析到自身的路径直接报错（防自启动递归/fork bomb）。
- 命名刻意用 `NolanguageEngine` 而非 `Nolanguage-<triple>`：Windows 大小写不敏感，后者会与安装器 `File /oname=Nolanguage.exe` 冲突并覆盖壳。

### 4.4 安装器从 Node SEA 换成 NSIS

旧 `installer/Nolanguage-Setup.exe`（176.9 MiB）是 Node SEA 自制安装器：双击弹黑框、无向导、无进度、安装目录写死。SEA 是 console 子系统，无法在运行时隐藏控制台，因此整条路径被 NSIS 取代，`installer/setup-entry.ts` 已删除。

## 5. 语言插件体系

三层根目录，统一 manifest 格式（`src/langs/Registry.ts`）：

| 来源 | 位置 | 可卸载 |
|---|---|---|
| 内置（官方） | `<home>/builtin`、仓库 `builtin/`、exe 内嵌解包目录 | 否（只能禁用） |
| 用户安装 | `<home>/languages/<id>@<version>/` | 是 |
| 宿主注入 | `LANG_DIR` 环境变量（`;`/`:` 分隔） | 否 |

`<home>` = `NOLANGUAGE_HOME` 或 `~/.nolanguage`；`config.json` 只存 `{"disabled": ["id"]}`。

打包版启动时 `materializeAssets('builtin')` 把内置插件释放到 `%TEMP%\nolanguage-embedded\builtin`，因此**安装完即自带 Python**，无需执行 `lang-install`。

### Python 插件能力（`builtin/python@1.0.0`）

| 项 | 值 |
|---|---|
| 扩展名 | `.py / .pyi / .pyw` |
| 运行 | `repl-session`（持久解释器，`{toolchain} -u` + `bootstrap.py`） |
| 超时 | **15 000 ms**（高负载脚本必须留余量） |
| LSP | pyright（缺失时回退内置 stub，`eager: true`） |
| 性能 | cProfile |
| 调试 | debugpy |
| 工具链发现 | `python` / `python3`、`PYTHON_BIN`、`C:/Python3xx/python.exe` |

### 安装版与源码版的命令差异

- 源码仓库：`npm run lang-install -- install|enable|disable|list ...`
- 安装版：**没有 node/npm，也没有 `scripts/lang-install.ts`**。等价手段：
  - 管理页 `http://127.0.0.1:7310/plugins`（启用/禁用/装第三方）
  - 手工放置第三方插件到 `%USERPROFILE%\.nolanguage\languages\<id>@<version>\`
  - 改 `~/.nolanguage/config.json` 的 `disabled`

## 7. 已知限制 / 待办

1. **进度条会短暂停顿**：90 MB 单文件写入后，杀软实时扫描期间进度停在 ~28%，日志仍在滚动。要完全平滑需换按字节自绘进度（NSIS 原生不支持）。
2. **Tauri 包是英文向导**：用的是 Tauri 默认模板（已含目录页与进度页），未做中文化；中文向导目前只有 `installer/Nolanguage-Setup.exe`。
3. **两套包的安装路径不同**：`Programs\Nolanguage` vs `Nolanguage`，同一台机器可并存，但会给排障带来混淆。
4. **MSI 未产出**：`tauri build` 全量构建依赖 WiX 下载，当前只跑 `--bundles nsis`。
5. **黑框的代价**：改为 GUI 子系统后，命令行启动不再有日志输出；需要日志时应使用源码模式或重定向。
6. **`tests/bench_cpu.py` 尚未运行**：只做了静态编写（`--scale` 上限 3.0，避免 15 s 超时）。
7. `installer/uninstaller/`（Rust 卸载器 crate）已不被 NSIS 路径使用，仅 `setup.ps1` 兜底方案仍参考它。

## 8. 常用命令速查

```powershell
# 构建
npm run build:exe                         # dist/Nolanguage.exe（GUI 子系统）
npm run build:setup                       # installer/Nolanguage-Setup.exe
.\node_modules\.bin\tauri.cmd build --bundles nsis   # Tauri 包

# 安装 / 静默安装
installer\Nolanguage-Setup.exe
installer\Nolanguage-Setup.exe /S /D=C:\Tools\Nolanguage

# 启动（NSIS 包）
& "$env:LOCALAPPDATA\Programs\Nolanguage\Nolanguage.exe"
& "$env:LOCALAPPDATA\Programs\Nolanguage\Nolanguage.exe" --open-browser
& "$env:LOCALAPPDATA\Programs\Nolanguage\Nolanguage.exe" --no-open

# 启动（Tauri 包）
& "$env:LOCALAPPDATA\Nolanguage\nolanguage.exe"

# 语言管理（仅源码仓库）
npm run lang-install -- list
npm run lang-install -- enable python
npm run lang-install -- install builtin/python@1.0.0

# 管理页面
Start-Process http://127.0.0.1:7310/plugins
```
