## 三、本地包安装（本次功能）的剩余缺口

功能链已通（清单 `dependencies.local` → 报告 `installLocal` → 对话框 → `installKind` + `path` → 引擎校验后 spawn），但还有四处没收尾：

| 缺口 | 现状 | 影响 |
|---|---|---|
| 只有 python 清单声明 `local` | go / java / javascript / markdown / zh-cn 与 `examples/` 下 c/cpp/rust 均无 `"local"` | 这些语言点 "From Path…" 会直接 toast "This language declares no local install"（`40-docks.js:264`）。js 加一个 `"path": {"args": [], "label": "Local folder or tarball"}` 即可用，无需改代码 |
| `dependencyStart` 不带 argv | 帧里只有 `{language, package, toolchain}`，真实命令事后才在 `dependencyResult.command` | 安装开始时面板显示 `$ editable: ./packages/my-lib`，看着像 shell 行但不是命令 |
| 没有"已装包指向源码"的门禁 | 方案要求的 `pip show -f` 断言未落地；现有测试只覆盖消息与 UI（`scripts/verify-pycharm.ts` 新增 5 条） | 真跑一次 pip 会改本机环境，所以自动化门禁只能断言 argv 形状，或放到隔离 venv 里跑 |
| 路径只校验"存在且在项目内" | 不校验目标是包（有无 `pyproject.toml`/`setup.py`），wheel 形态也不校验扩展名 | 传错目录时错误来自 pip 的报错，不是面板的 |

## 五、明确不做（有理由，不是待办）

| 项 | 理由 |
|---|---|
| 多光标 | 需迁 CM6（ESM 多包 + 打包器），与"零构建、单文件自包含"两条不变量冲突 |
| 多根工作区 | 要改 `WorkspaceService` 的 root 模型（每根一套 slot + LSP），5–8d，且现有 50+ 套件多处假设单根 |
| PTY 终端 | Windows 侧需要 conpty/node-pty，与"零运行时依赖"冲突 |
| 非 stdio MCP | 传输层未做，且当前设计只面向本地 stdio 服务器 |
| 非 Python 覆盖率 | 各语言没有解释器级的行覆盖原语，接一个只会得到百分比谎言 |
| Optimize Imports 删"未使用 import" | 需要解析器，现有实现只去重 + 排序 |
| 生成工程时联网拉依赖 | 拉取是独立按钮，脚手架不偷偷联网 |

## 六、建议顺序

1. **测试运行器**（2d）—— 唯一"每天都在用却完全没有"的面板，且解析器可纯函数单测。
2. **Inlay Hints**（1.5d）—— 与折叠共用 LSP 链，链路已有先例，风险低。
3. **javascript 清单加 `local`**（10 分钟）—— 让"两个包一起开发"这套能力不止 Python 能用。
4. **插件 sha256 校验**（0.5d）—— 字段已声明、消费方为空，属于"看起来有保护其实没有"。
5. Inlay / 测试树之后再谈 AI 侧栏（要先定协议与密钥存放）。
