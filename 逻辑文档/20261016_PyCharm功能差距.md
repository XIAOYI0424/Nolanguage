# PyCharm 风格外壳：与真实 PyCharm 的功能差距分析（修订版）

> 生成日期：2026-10-16
> 修订日期：2026-10-16
> 范围：默认工作区 `/`（PyCharm 外壳，`src/panel/pycharm-ui.ts`）+ 后端 `src/panel/server.ts`、`WorkspaceService.ts`、`FsService`、`python/` LSP、`exec/` 执行平面。
> 结论：当前是一个**高保真 UI 外壳 MVP**——外观、布局、主题、片段交互已到位，但核心价值链（编辑 → 保存 → 智能补全 → 运行 → 调试 → 提交）尚未打通。多数"高级功能"是**占位/演示**，或**后端已具备但前端未接入**。

---

## 0. 编辑器底层技术栈（关键前提）

在阅读后续所有差距分析前，必须先明确一个决定一切的前提：

| 项 | 现状（推测/需确认） | 影响 |
|---|---|---|
| 编辑器底层 | **原生 `<textarea>`**（从"textarea 旁弹出补全"推断） | 决定所有编辑器智能功能是"接线"还是"重写" |
| 语法高亮 | 正则分词 + overlay 装饰 | 能凑合 Python，多语言会失效 |
| 光标定位 | 无像素级定位能力 | **无法做内联补全气泡、幽灵文本、多光标** |
| 装饰层 | DOM overlay | 波浪线、inlay hints 受限 |
| 大文件性能 | 未测 | textarea 在 > 5000 行时会明显卡顿 |

**结论**：**编辑器底层升级（textarea → CodeMirror 6）是 P0 级独立工程，而非"顺手改改"**。它决定了：

- 补全能否以内联气泡呈现（vs. 侧边列表）
- hover 能否做精确定位气泡
- 折叠能否语言感知（vs. 缩进启发式）
- 多光标、幽灵文本、inlay hints 是否可能
- 大文件编辑是否流畅

**如果不做此升级，后续所有编辑器相关功能都会遇到天花板。**

2. 前端需**语法高亮切换**（当前仅 `PY_PATTERN`）
3. 前端需**补全/hover 语言路由**
4. UI 需**文件类型 → 语言映射**
5. 需要**编辑器底层支持**（见 §0）

**接入路径评估**（原文档缺失）：

| 子功能 | 实现路径 | 工期 |
|---|---|---|
| 分支状态显示 | 调用 `git status --porcelain` 解析 | 1 天 |
| diff 视图 | 文本对比算法 + UI（可用 `diff` 库） | 3–5 天 |

**结论**：VCS 是独立子系统，非"接几个端点"能完成。建议拆为 P2.1（基础状态+提交）、P2.2（diff）、P2.3（高级）三档。

## 4. 关键差距（一句话每条）

1. **编辑器底层是 textarea，不是真编辑器**——所有高级功能的天花板
2. **没有真实文件系统**——所有编辑都是临时的
3. **没有 LSP 智能**——编辑体验停留在记事本级别
4. **没有调试器**——断点只是视觉标记
5. **没有 Git**——VCS 面板是装饰
6. **没有设置持久化**——刷新即复位
7. **没有测试运行器**——pytest 集成缺失
8. **没有 PTY 终端**——交互式程序无法运行
9. **没有多语言切换**——Go LSP 后端闲置
10. **没有状态同步**——多窗口、多标签状态不一致

## 5. 最小可用 IDE 的定义

**定义**：

> 一个用户能**打开真实项目**、**编辑文件**、**保存**、**运行**、**看到结果**，且**刷新后状态不丢失**的 IDE。

按此定义，当前外壳距离"最小可用 IDE"的差距是：

| 序号 | 差距 | 对应阶段 |
|---|---|---|
| 1 | 真实文件系统接入（打开/编辑/保存/落盘） | P0.1 |
| 2 | 状态持久化（主题、布局、打开标签） | P0.4 |
| 3 | 编辑器底层升级（textarea → CodeMirror 6） | P0.2 |

**其他所有（补全、调试、Git、测试、PTY）都不是"最小可用"的必需项**——它们属于"好用 IDE"和"完整 IDE"的范畴。

这个定义的实用价值：**让 P0 范围收敛到 3 项，而非原文档的 2 项+隐含的第 3 项**。

## 6. 优先级路线（修订版）

原文档 P0 缺少依赖排序与工期估算。修订如下：

### P0：最小可用 IDE（3–4 周）

```

      ├─ 影响：Save、工程树、标签页全部激活

      ├─ 前置：P0.1 + P0.2
      ├─ 影响：IntelliSense、悬浮提示

P0.4  状态持久化（localStorage）                   1–2 天
      ├─ 前置：无
      ├─ 影响：主题、布局、标签刷新保持
      └─ 风险：低
```

**P0 完成后**：用户可打开真实项目、编辑、保存、运行、补全、重启后继续。

### P1：好用 IDE（3–4 周）

## 8. 一句话总结

当前 PyCharm 外壳 **"形已具、神未足"**：外观、布局、主题、片段交互（运行/终端/诊断/性能/日志/搜索/扩展）真实可用，但**文件持久化、编辑器底层、编辑器智能、调试器、Git、设置持久化**要么纯占位 demo，要么后端已就绪却未接入前端。

**最高杠杆的下一步是 P0 的三项**：

1. **真实文件系统接入**（3–5 天，低风险，后端已就绪）
2. **编辑器底层升级 textarea → CodeMirror 6**（1–2 周，中风险，决定编辑器智能天花板）
3. **状态持久化**（1–2 天，低风险，最小可用 IDE 的收尾）

这三项完成后，即可宣布"最小可用 IDE"落地；此后的补全、调试、Git、测试均建立在稳固的底座之上。

**在动工前，请先确认 §0 的编辑器底层现状**——它决定了后面所有编辑器相关功能是"接线"还是"重写"。

## 9. 轻量化约束（落地提醒）

平台核心理念是「性能优先、自监测、轻量化」。P0 改造须守住此底线，避免为补功能而引入重依赖：

- **P0.2 的 CodeMirror 6 是重依赖**（约数百 KB + worker）。若"轻量化"为硬约束，可评估更轻的替代：CodeMirror 5（单一包、无 worker）、或更薄的"textarea + 自绘 overlay"增强（仅补全列表/装饰，不换底层）。取舍：轻量路线会牺牲 §0 列出的内联气泡/多光标/精确 hover，退回到"侧边列表式补全"。
- **P2.4 的 node-pty / portable-pty 带原生编译**，会增大打包体积与构建复杂度；管道式终端已能跑 `input()` 类交互，PTY 仅对 vim/htop/颜色/Ctrl+C 有意义，属"好用"而非"必需"。
- **P2 的 VCS / Database / Profiler 等应做成按需加载的扩展面板**，默认不进主包，保持核心轻量。
- 任何新依赖都应在 `package.json` 标注并纳入 CI 体积门禁（当前 `dist/Nolanguage.exe` 89.4 MiB），P0 后若超阈值需回砍。

### 10.1 P0.2 交付明细（路线 A：textarea + 自绘 overlay）

- **分语言分词高亮**：新增轻量分词器 `tokenizeRules` + `LANG_RULES`（go / json / markdown / yaml / javascript(ts) / html / css）；Python 沿用 `PY_PATTERN`。规则用字符类与前瞻/后顾替代 `\d \w \s \b`，且**不引入任何依赖**。
- **自动缩进**：Enter 后按当前行缩进，行尾为 `: { ( [` 时再进一级；行尾已是闭合符时展开为三行。
- **括号 / 引号自动闭合**：圆括号、方括号、花括号、单/双引号与反引号成对插入并越过已有闭合符；有选区时包裹选区。
- **当前行高亮**：`#curline` 覆盖层随光标与滚动同步。
- **LSP 补全**：输入去抖 130ms → `complete`；`#cmp` 弹窗按前缀过滤，↑/↓ 选择、Enter/Tab 接受、Esc 关闭、Ctrl+Space 手动触发。
- **LSP hover**：悬停 450ms → `hover`（按鼠标坐标估算词位置）；`#hoverTip` 气泡显示。
- **语言路由**：`lspLang()` 仅在 Python / Go 时发送 `check` / `complete` / `hover`（后端 LSP 仅支持这两种），运行同样受限并给出提示。

**仍未覆盖（路线 A 的固有取舍）**：内联补全气泡、多光标、幽灵文本、inlay hints、语言感知折叠、超大文件性能（> 20 万字符回退为纯文本）。若要这些，需回到 §0 的 CodeMirror 路线。

**验证**：`verify-pycharm` 34 → **42** 项（新增自动闭合 / 自动缩进 / 补全弹窗 / hover 气泡端到端断言）；`verify-all` **821 / 821（16 套件）**，内联脚本仍自包含且可解析。

**下一步**：P0.4（状态持久化，localStorage 保主题 / 布局 / 打开标签）。
