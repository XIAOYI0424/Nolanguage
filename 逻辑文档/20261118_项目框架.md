## 一、定位

Nolanguage 不是"一个 IDE 仓库"，而是三件东西共用一份引擎：

| 产物 | 入口 | 形态 |
|---|---|---|
| 工作台（IDE） | `src/panel/server.ts` + `src/ui/` | 单页 Web 应用，CodeMirror 内联，零外部资源 |
| 桌面壳 | `src/desktop/main.ts` | Node SEA 单文件 exe，自带 HTTP/WS 服务 + Edge/WebView2 `--app` 窗口 |
| 观测工具（ndebug） | `src/debugtool/` | 独立产品，共用 `util`/`net`/`assets`/`vendor`，不依赖外壳与内核 |

技术基线：TypeScript（NodeNext `.js` 说明符）直接由 `node --experimental-transform-types`
运行，或 `tsc` 编译；**运行时依赖 0 个**（`package.json` 无 `dependencies`），开发依赖 8 个；
CodeMirror 5.65.21 以 vendor 形式内联（`src/vendor/codemirror/`），不走 CDN 也不是 npm 依赖。

规模现状（`npm run verify:arch` 输出）：`197` 个 `.ts` 文件、`571` 条 import、切片图是一个 DAG
（`22/22` 层序检查通过，`allowedCycles` 为空——一组已记账的环都没有）。`budgetExceptions` 目前
只剩一条：`panel/WorkspaceService.ts`（1258 行，超 1200 行预算，账本里写着拆分计划）。

## 二、代码地图

`src/` 下每个一级目录是一个**切片（slice）**。层号取自 `scripts/architecture.json` 的 `layers`
（这是账本里的**意图**，不是从代码里推出来的），括号内是该目录下全部文件数（含 `.js`/`.css`，
共 242 个文件、197 个 `.ts`；预算里的"25 个文件"只数 `.ts`，所以 `ui` 的 26 个文件对应 12 个
`.ts`，不算超预算）：

```
层 0   util(9)  net(1)  assets(1)  git(1)  vendor(21)
层 1   correlation(2)  ui(26)
层 2   log(9)
层 3   store(5)  scaffold(6)
层 4   perf(10)
层 5   kernel(6)
层 6   runtimes(11)  lsp(18)  mcp(1)
层 7   langs(21)
层 9   go(2)  python(4)  markdown(3)  extensions(13)  dap(2)
层 10  profiler(6)  exec(6)  commands(2)
层 11  js(2)
层 12  panel(25)
层 13  desktop(5)
层 14  cli(2)
层 15  debugtool(18)
层 16  (root)  index.ts（组合根）  version.ts  demo.ts  demo-extensions.ts
```

`ui` 站在层 1（页面是纯字符串渲染，只依赖 `vendor`），`scaffold` 在层 3（它是模板/依赖数据，
被更高层的 `panel`/`commands` 消费）。

规则只有一条方向：**箭头只能朝下**。零 import 的 `types.ts` 是"共享词汇"，任何层可引用。
单文件 ≤ 1200 行、单切片 ≤ 25 文件是硬预算（`scripts/architecture.json`）。

## 三、内核层：三总线 + 双脊柱

```
                 ┌──────────────────────────────┐
                 │            Kernel            │
                 │  CommandBus · EventBus       │
                 │  ServiceRegistry             │
                 │  LogSpine(日志脊柱)          │
                 │  PerfSpine(性能脊柱)         │
                 └───────┬──────────┬───────────┘
                         │          │
              CorrelationBus     SqliteStore
              (请求/事件/日志     (日志温层、性能
               串成一条链)        记录、baseline)
```

| 文件 | 职责 |
|---|---|
| `src/kernel/Kernel.ts` | 组装：注册三总线、启动/停止服务、串联脊柱 |
| `src/kernel/CommandBus.ts` | 命令注册 + 中间件 + 埋点（`command.*`） |
| `src/kernel/EventBus.ts` | 事件订阅 + 通配埋点 |
| `src/kernel/ServiceRegistry.ts` | 服务生命周期（init/start/stop，依赖排序） |
| `src/kernel/LogSpine.ts` | 日志管线装配（级别、采样、传输） |
| `src/perf/PerfSpine.ts` | 指标/采样/span 装配，通过 `perf/host.ts` 的端口接口回看内核（**不再反向依赖 kernel**） |
| `src/correlation/CorrelationBus.ts` | 把命令、事件、日志记录挂到同一个 `correlationId` |
| `src/store/SqliteStore.ts` | 温层落盘（日志、指标、baseline），轮转有上限 |

关键设计：`perf` 不认识 `kernel`——`perf/host.ts` 声明端口（`onCommand` / `tracer` /
`logger` / `events` / `services`），由 kernel 侧适配。这是 0.7.13 解开 `kernel ↔ perf` 环的方式。

## 四、传输与路由层（`panel`）

```
浏览器/WebView           引擎进程
┌────────────┐   ws      ┌────────────────────────────────────────┐
│ 页面 JS     │ ⇄  ────  │ net/websocket.ts ⇄ Transport.ts        │
│ (11 分片)   │  stdio   │        │                               │
└────────────┘ (sidecar) │        ▼ switch(msg.kind)              │
                         │   server.ts  ── 76 种消息 ── handlers/ │
                         │        │                               │
                         │        ├── WorkspaceService（每语言 slot）│
                         │        ├── FsService（真实文件系统）      │
                         │        ├── PanelHub（连接广播）           │
                         │        └── McpManager / LspManager / ... │
                         └────────────────────────────────────────┘
```

| 文件 | 职责 |
|---|---|
| `panel/server.ts` | HTTP 路由 + `switch (msg.kind)` 分派（不 spawn 进程、不持会话） |
| `panel/Transport.ts` | WebSocket ⇄ stdio 同一协议，两种运输 |
| `panel/handlers/run.ts` | 唯一 spawn 子进程、持 DAP 会话的处理器（term/run/debug/runScript） |
| `panel/handlers/{fs,languages,navigation,perf,plugins,attribution,migration}.ts` | 其余分派目标 |
| `panel/WorkspaceService.ts` | 每个语言一个 slot、LSP 客户端、活动运行 |
| `panel/workspace-wire.ts` | slot → 状态栏/插件页消费的 JSON（状态的**投影**） |
| `panel/conn-state.ts` | 每连接状态；`takeConnection()` 删除并返回，不留漏删窗口 |
| `panel/pycharm-ui.ts` | 把 HTML 外壳拼出来（留在 `panel`，因为它要读插件根目录） |

HTTP 页面路由：`/`、`/ide`、`/pycharm`（PyCharm 外壳）、`/monitor`、`/panel`（监控页）、
`/perf`、`/profile`、`/extensions`、`/plugins`、`/languages`、`/health`。`/` 的 HTML 按
`Accept-Encoding` gzip，压缩结果进程内缓存。

## 六、语言体系（`langs` + `runtimes`）

**零硬编码**：引擎不认识任何一种语言。一个语言 = 一份 `manifest.json`：

```jsonc
{
  "id": "python", "version": "1.0.0", "apiVersion": "^1.0.0",
  "trust": { "sandbox": "subprocess" },
  "file": { "extensions": ["py"], "defaultExt": "py", "fileName": "main.py" },
  "grammar": { "rules": [ { "re": "...", "cls": "k" } ] },      // 高亮规则
  "lsp": { "discovery": {...}, "command": [...], "provider": {...}, "manager": true },
  "run": { "mode": "repl-session", ... },                       // 五运行时之一
  "debug": { "adapter": "debugpy", ... },                       // DAP
  "profiler": { ... },                                          // 剖析
  "dependencies": { "format": "requirements", "files": [...] },
  "scaffold": { "templates": [ ... ] }                          // 新建项目模板
}
```

插件解析链路：

```
langs/pluginRoots.ts   扫描五层：project → builtin → user → cli → system
      ↓
langs/layers.ts        版本高者胜；同版本先扫描的先到先得
      ↓
langs/overrides.ts     合并 <home>/overrides/<id>.json（对象递归、数组整体替换、null 删键）
      ↓
langs/manifest.ts      校验（非法覆盖被忽略并报出来，而不是让语言消失）
      ↓
langs/Registry.ts      对外提供语言描述；RunnerFactory 依据 run.mode 造运行时
```

五种运行时（`src/runtimes/`，完整列表就在 `index.ts`）：

| 运行时 | 语义 | 谁用 |
|---|---|---|
| `template` | 编译/执行命令模板，真实子进程 | Java、C/C++、Rust |
| `repl-session` | 常驻解释器会话，变量跨次保留 | Python |
| `directory-session` | 固定步骤列表（`go build` → 产物） | Go |
| `inline-vm` | 进程内 `vm` 求值，无 argv | JavaScript |
| `script-host` | 插件自带 `runtime.js` 解析一切 | 需要自定义逻辑的插件 |

`supportsArgs` 与代码一致性由 R8 校验：声明为真的运行时必须真读 `opts.args`。

工具链与依赖：`langs/discover.ts`（发现二进制）、`interpreters.ts`（解释器选择）、
`toolchainEnv.ts`（环境变量）、`dependencies.ts`（六种生态的解析/安装）、
`serverInstall.ts`（语言服务器托管安装）、`versionCache.ts`、`SourceResolver.ts`（zip/tar/url/git）。

## 七、语言服务（`lsp`）

```
WorkspaceService ── per-language slot ──► LspClient（jsonrpc 2.0，长度前缀帧）
                                              │
                     ┌────────────────────────┴────────────────────────┐
                     │  默认：一语言一客户端（可逆，逐 manifest 迁移）    │
                     │  可选：manager: true → LspManager                │
                     │     LspPool / Scheduler / strategies             │
                     │     bundledFallback / fallback / CacheValidator  │
                     └─────────────────────────────────────────────────┘
```

- 禁用/降级是**声明**的：`lsp.disabled` 表示这门语言故意没有服务器，`requiresProjectFile` 缺失
  时是"降级"而不是"坏了"，`degradedNote` 是给用户看的原因。
- `bundledFallback` 让平台在发现失败时启自带服务器，命令由插件声明，引擎不知道语言名。
- `ttlStats.ts` + `manager/LspPool` 管空闲回收；`memoryHint` 只是估算，不是 RSS。
- 超时可配（`diagnosticsTimeoutMs` / `coldDiagnosticsTimeoutMs`），不是按语言分支的常量。

## 八、执行平面（`exec`）

`SandboxPool` 是**常驻 warm worker 池**，与 IDE 的 Run（冷启动 runner）分开，互不回归：

| 语言 | "热"的含义 |
|---|---|
| Python | 常驻解释器，namespace 跨次保留 |
| JavaScript | 复用进程，每个片段在全新 `vm` 上下文里跑 |
| Go | 保留一个 scratch 目录（模块与文件写完就留着），工具链只解析一次 |

并发模型：`sessionTails` 按 session 串行化 `run` 与 `reset`——同一 session 有序，不同 session
并行；session id 绑定语言，拿 Python 的 id 跑 JS 会明确报错。上限
`SANDBOX_MAX_WORKERS=8`，命名会话满即拒绝，只有匿名会话按 LRU 回收。

## 十、启动与生命周期

```
Nolanguage.exe
 ├─ 无参数               → 起服务 → 找 WebView2 ─┬─ 有：Edge/WebView2 --app 窗口（无浏览器 chrome）
 │                                              └─ 无：系统默认浏览器
 ├─ --open-browser       → 起服务 + 系统浏览器
 ├─ --no-open/--no-browser → 只起服务（CI/无头）
 ├─ --panel-stdio        → 面板协议走 stdin/stdout（Tauri sidecar）
 ├─ --dump-plugins       → 打印插件分层，然后在退出前返回（不起服务）
 └─ lang <verb>          → 语言插件 CLI（与 nlg lang 同实现）
```

窗口即生命周期：关窗 → 结束服务 → 语言服务器/worker/SQLite 一并收尾。同端口已有实例时不再起
第二套服务；崩溃遗留的孤儿窗口在下次启动时清理（`desktop/handshake.ts` + `session.ts`）。
数据目录分两处：插件与项目数据在 `~/.nolanguage`（`NOLANGUAGE_HOME` 可改），应用状态
（SQLite、WebView2 缓存）在 `%LOCALAPPDATA%\Nolanguage`（`NOLANGUAGE_DATA` 可改）——卸载删程序
目录时不会被 WebView 锁住的缓存拖住。

## 十二、必须遵守的不变量（改了就会坏）

1. **引擎零语言分支**：新增一门语言只能加 manifest，不能在 `src/` 里写 `if (language === 'x')`。
2. **客户端分片禁止反引号**，只允许 `${iconsJson}`、`${i18nJson}`、`${patternJson}`、
   `${mainJson}`、`${utilsJson}`、`${jsJson}`、`${readmeJson}` 这几个种子 token 插值。
3. **单文件自包含**：页面不得出现外部 `<script src>`、`<link>`、`@import`、CDN 或绝对 URL。
4. **写入要等 ACK**：标签页只在磁盘回执到达后清 dirty；失败回执不得关标签。
5. **越界拒绝**：文件与构建文件编辑都做 `realpath` 校验，项目目录之外一律拒绝。
6. **账本只能缩小**：`scripts/architecture.json` 新增违规失败、违规变多失败、违规消失也失败。
7. **不引运行时依赖**：`package.json` 的 `dependencies` 必须保持为空。
