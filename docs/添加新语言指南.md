# 添加一门新语言（插件方式）

> **不要改引擎代码。** 一门语言 = 一个目录 + 一份 `manifest.json`。
> 本指南按"你要提供什么能力"分档，每档给出可复制的最小 manifest 与验证方法。

相关设计：`语言插件化设计.md`（契约、运行时、边界）。
契约源码：`src/langs/manifest.ts`（类型 + 校验）、`src/runtimes/types.ts`（`RunConfig`）。

---

## 0. 三十秒版

```
builtin/<id>@<version>/          ← 官方预装（随二进制分发，不可卸载）
languages/<id>@<version>/        ← 用户安装（可卸载）
    manifest.json                ← 必需
    bootstrap.py | runtime.js    ← 可选（会话持久化 / 自定义运行逻辑）
    icon.svg                     ← 可选
```

`manifest.json` 最小可用形态：

```json
{
  "id": "demo",
  "displayName": "Demo",
  "version": "1.0.0",
  "apiVersion": "^1.0.0",
  "file": { "extensions": ["dm"], "defaultExt": "dm" },
  "grammar": { "rules": [{ "re": "//[^\\n]*", "cls": "c" }] }
}
```

只有这些，它就是一门"能高亮、能编辑、不能运行"的语言。加上 `run` 才能 Run，
加上 `lsp` 才能 Check / 悬停。

**补全不用声明**：L1（内置词法补全）默认对所有语言开启，从当前文档里提取
"看起来像标识符"的 token 作为候选，不解析语法、不区分语言、不依赖 LSP。
`lsp` 只是让 L2（精确补全）叠加在它上面。

**`builtin/` 与 `languages/` 的格式完全相同**——差别只有来源和能否卸载。
不要为"官方语言"写特例分支，那正是插件化要消灭的东西。

## 1. 八个面（按需提供）

| 面 | 字段 | 没有它会怎样 |
|---|---|---|
| 1. 文件类型 | `file.extensions` | 打开文件认不出语言 |
| 2. 语法高亮 | `grammar.rules` | 纯文本显示 |
| 3. 语言服务 | `lsp` | Check / 悬停不可用；补全退回 L1（Run 仍可用） |
| 4. 运行 | `run` | Run 按钮禁用（"documents render"） |
| 5. 脚手架 | `scaffold` | 需要项目文件的工具链跑不起来 |
| 6. 性能分析 | `profiler` | 不能 Profile；`adapter` 未知会**报错**而非静默换工具 |
| 7. 调试 | `debug` | 不能设断点 / 单步；降级时显示 `degradedNote` |
| 8. 数据迁移 | `migrations` | 升级后旧数据格式可能读不了 |

> **高亮有两条路径**：桌面/浏览器默认用内置的 CodeMirror 5，它按
> `cmModeFor()` 把语言 id 映射到 CM mode；`grammar.rules` 服务于没有 CM 模式时的
> textarea 回退，以及文件类型目录。两条路径互不阻塞——没有 CM 模式不会报错，
> 只是 CM 里显示为纯文本。

### L1 补全的开关（默认不用管）

L1 是**默认开启**的：`contributes` 里什么都不写，就有"当前文件里出现过的标识符"
作为补全候选。只有文本本身不适合提取标识符的语言才需要显式关掉——Markdown 就是
这么做的（每个英文单词都会被当成候选）：

```json
"contributes": {
  "completion": { "lexical": { "enabled": false } }
}
```

`Nolanguage.exe --dump-plugins` 的每行会打印 `lexical on|off`，用它确认最终生效值。

## 2. 面 1–2：文件类型与高亮

```json
"file": { "extensions": ["rs", "rlib"], "defaultExt": "rs", "fileName": "main.rs" },
"grammar": {
  "rules": [
    { "re": "//[^\\n]*", "cls": "c" },
    { "re": "/\\*[\\s\\S]*?\\*/", "cls": "c" },
    { "re": "\"([^\"\\\\]|\\\\.)*\"", "cls": "s" },
    { "re": "\\b(?:fn|let|mut|pub|impl|struct|enum|match)\\b", "cls": "k" },
    { "re": "[0-9][0-9_]*(?:\\.[0-9]+)?", "cls": "n" },
    { "re": "[A-Za-z_][A-Za-z0-9_]*(?=\\()", "cls": "f" }
  ]
}
```

- `cls` 取值：`c` 注释 / `s` 字符串 / `d` 装饰器·属性 / `k` 关键字 / `n` 数字 / `b` 内建 / `f` 函数调用 / `cl` 类名。
- 规则按**数组顺序**尝试，首个命中生效——注释和字符串要排在最前面。
- 每条正则会被编译成**粘性正则**（`y` 标志），必须能匹配"从当前位置开始"的内容。
  需要行首锚点时加 `"flags": "m"`。
- **校验期会 `new RegExp` 一次**：一条编译不过的正则会让整个插件被拒绝，
  因为坏规则会让整门语言静默失去高亮。

> **CodeMirror 高亮**：在 `src/ui/pycharm-client.ts` 的 `cmModeFor()` 里把语言 id
> 映射到 CM mode（如 `rust`），并把 `mode/rust/rust.js` vendor 到
> `src/panel/vendor/codemirror/mode/rust/`、在 `src/ui/codemirror-assets.ts` 里 import。
> `grammar.rules` 仍会通过 `workspace` 消息送到页面，由 `RULES` 自动合并，用于
> textarea 回退；没有 CM 模式时也能正常编辑，只是不高亮。

## 3. 面 3：语言服务

```json
"lsp": {
  "discovery": {
    "commands": ["rust-analyzer"],
    "envVars": ["RUST_ANALYZER_PATH"],
    "knownPaths": ["~/.cargo/bin/rust-analyzer"]
  },
  "command": ["{resolved}"],
  "args": ["--stdio"],
  "languageId": "rust",
  "serverName": "rust-analyzer",
  "memoryHint": "500MB",
  "requiresProjectFile": "Cargo.toml",
  "diagnosticsTimeoutMs": 8000,
  "coldDiagnosticsTimeoutMs": 30000,
  "degradedNote": "未找到 Cargo.toml，补全和诊断能力受限"
}
```

发现顺序固定为 **`versionFiles`（排序提示）→ `envVars` → `knownPaths` → `commands`（PATH）**：

- 环境变量优先，因为一台机器装多个版本时它是唯一的显式开关；
- 绝对路径次之，因为 Windows 安装常常根本不改 PATH（本机 Go 就在 `D:\Go lang`）；
- PATH 最后，因为它是最不具体的答案。

### 版本声明文件（可选，推荐）

`discovery` 可以读项目的版本声明，用它**给候选排序**（不是硬性约束）：

```json
"discovery": {
  "versionFiles": [
    { "path": ".python-version", "format": "plain" },
    { "path": "package.json", "format": "json", "key": "engines.node" },
    { "path": "go.mod", "format": "regex", "pattern": "^go\\s+(\\S+)" },
    { "path": "pyproject.toml", "format": "toml", "key": "project.requires-python" }
  ],
  "knownPaths": ["~/.pyenv/versions/*/bin/python3"]
}
```

- `format`：`plain`（第一行）/ `json`（点路径）/ `toml`（只认单个 `key = "value"` 行，不是完整 TOML）/ `regex`（捕获组 1）。
- `knownPaths` 支持**单段 `*`**（如 `~/.pyenv/versions/*/bin/python3`），不支持 `**`。
- 版本文件只是**提示**：`.python-version` 写 `3.11.4` 时，`3.11.4` 的候选排在前面；没装就回落到最近的已装版本，不会报错。
- 显式 `envVars` 仍然最优先。

全部落空 → 状态栏显示 `degradedNote`，**Run 仍然可用**（这是"降级"不是"坏掉"）。

`bundledFallback: "stub"` 是给 Python 用的：平台自带一个最小服务器作为 pyright 的回退。
它是一个**有名字的能力**，不是 `if (language === 'python')`。

## 4. 面 4：运行（选一个运行时）

`run.mode` 必须是五种之一。选错了不会崩，会在 `RunnerFactory.create()` 报出具体原因。

### 4.1 `template` —— 编译再运行（Rust / C / C++ / Java / C#）

```json
"run": {
  "mode": "template",
  "requires": ["template@^1.0.0"],
  "timeoutMs": 20000,
  "sourceExt": ".c",
  "discovery": { "commands": ["gcc"], "envVars": ["CC"] },
  "steps": [
    { "role": "build", "cmd": "\"{toolchain}\" {file} -o \"{workdir}/a{exe}\"" },
    { "role": "run",   "cmd": "\"{workdir}/a{exe}\"" }
  ]
}
```

- 占位符：`{file}` `{workdir}` `{basename}` `{data}` `{toolchain}` `{exe}`。
- 含空格的路径**必须用双引号包起来**（`"{toolchain}"`），否则会被拆成多个参数。
- `role: "build"` 失败 → 结果是 `compileError: true` + `phase: "build"`，
  UI 说"编译错误"而不是给一个程序根本没跑起来的退出码。
- 第一步失败即停止。

> 现成可装的一份：`examples/cpp@1.0.0/` —— C++ 版 `template`，含 8 个扩展名、clangd、`g++/clang++` 发现、`modes.test`、codelldb。

### 4.2 `repl-session` —— 需要跨 run 保留状态（Python / Lua / Ruby）

```json
"run": {
  "mode": "repl-session",
  "requires": ["repl-session@^1.0.0"],
  "timeoutMs": 15000,
  "command": ["{toolchain}", "-u"],
  "sourceExt": ".py",
  "bootstrap": "bootstrap.py",
  "discovery": { "commands": ["python", "python3"], "envVars": ["PYTHON_BIN"] }
}
```

运行时**不认语言**，它只保证三件事：一个稳定的会话目录、源码文件写在哪里、
以及一个可选的 `bootstrap` 脚本。持久化机制由你的 bootstrap 实现，环境变量是契约：

| 变量 | 含义 |
|---|---|
| `NL_SESSION_DIR` | 该 session 的稳定目录 |
| `NL_SOURCE_FILE` | 本次要执行的源码 |
| `NL_GLOBALS_FILE` | 你可以在哪儿持久化状态 |
| `NL_LANGUAGE` | 插件 id（诊断用） |

没有 `bootstrap` 时，运行时会直接 `command + [源码路径]`——适合本来就不需要持久化的解释器。

### 4.3 `directory-session` —— 需要模块目录（Go / 需要工程文件的编译器）

```json
"scaffold": {
  "required": true,
  "onFirstRun": [{ "file": "go.mod", "template": "module demo\n\ngo 1.21\n" }],
  "projectFiles": ["go.mod"]
},
"run": {
  "mode": "directory-session",
  "requires": ["directory-session@^1.0.0"],
  "sourceExt": ".go",
  "command": ["{toolchain}"],
  "discovery": { "commands": ["go"], "envVars": ["GO_BIN"] },
  "steps": [
    { "role": "build", "cmd": "\"{toolchain}\" build -o \"{workdir}/main{exe}\" {file}" },
    { "role": "run",   "cmd": "\"{workdir}/main{exe}\"" }
  ],
  "modes": {
    "test": { "timeoutMs": 60000, "steps": [{ "role": "test", "cmd": "\"{toolchain}\" test -v -count=1 ." }] }
  }
}
```

- `scaffold.onFirstRun` 在会话目录首次使用时写入（已存在则跳过），同时也会写进工作区目录，
  供语言服务器识别工程。
- `modes` 里每个 key 都成为一个可运行的 mode（UI 的 Test 按钮就是 `mode: "test"`）。
- 会话目录按 mode 换文件名（`main.go` / `main_test.go`），**运行时会清掉其他 mode 的入口文件**，
  否则上一轮带编译错误的 `main.go` 会让 `go test` 直接构建失败而不是报告失败的测试。

### 4.4 `inline-vm` —— 进程内 VM（JavaScript / 任何 ECMAScript 形状的语言）

```json
"run": { "mode": "inline-vm", "requires": ["inline-vm@^1.0.0"], "sourceExt": ".js", "vmTimeoutMs": 5000 }
```

每次 run 一个**全新上下文**（这正是"带顶层 `const` 的片段能反复 Run"的原因），
带墙钟上限。不能用于非 ECMAScript 语言——那种情况用 `script-host`。

### 4.5 `script-host` —— 自己的运行逻辑（特殊语言）

```json
"run": { "mode": "script-host", "requires": ["script-host@^1.0.0"], "sourceExt": ".xx", "script": "runtime.js" }
```

`runtime.js` 跑在**子进程**里（不是 Worker：Worker 共享堆和崩溃域，隔离不足），
stdin/stdout 上是行分隔 JSON：

```
→ { op:'run', code, file, mode, sessionId, sessionDir, dataDir, timeoutMs }
← { t:'out', s:'stdout'|'stderr', text }
← { t:'exit', code }
```

非 JSON 行按用户输出处理，所以"只 `console.log`"的脚本也能用。超时 `SIGKILL`，
堆上限 `--max-old-space-size=256`。

## 5. 面 5–6：脚手架与性能分析

`scaffold` 见 §4.3。`profiler` 的 `adapter` 是**工具名**（平台注册的那一个），
不是语言名 —— 未知 adapter 会在调用时报错，不会静默用别的工具兜底：

```json
"profiler": { "adapter": "cProfile", "memoryHint": "80MB" }
```

当前平台注册的工具：`cProfile`（Python `cProfile`）、`pprof`（Go `runtime/pprof`）。
`memoryHint` 同时喂给 Phase 4 的内存预算（格式 `380MB` / `1.5GB` / 裸数字=字节）。

### 5.1 面 7：调试（可选）

```json
"debug": {
  "adapter": "debugpy",
  "type": "python",
  "discovery": { "commands": ["debugpy-adapter"], "envVars": ["DEBUGPY_ADAPTER"] },
  "command": ["{resolved}"],
  "args": [],
  "serverName": "debugpy",
  "memoryHint": "60MB",
  "degradedNote": "debugpy not installed - debugging is unavailable for Rust"
}
```

`command` 里没有 `{resolved}` 时视为绝对路径，**不需要 discovery**；两者都不行 →
`available: false`，`startDebugSession()` 抛错并带上你写的 `degradedNote`。

### 5.2 面 8：数据迁移（升级时）

插件体整体替换，`data/<id>/` 不替换。数据结构变了就声明迁移步骤，
每一步是插件内一个普通 Node 脚本，参数是 `<dataDir> <from> <to>`：

```json
"migrations": [{ "from": "1.0.0", "to": "1.1.0", "file": "migrations/rewrite.js" }]
```

- 同版本重装**不重跑**（`data/<id>/migrations.json` 记录已执行步骤）
- 脚本退出码非 0 → **整个安装中止**，旧版本保持可用
- 别在安装路径里做「顺手改数据」之外的事：脚本跑在子进程里，没有宿主上下文

## 6. 装上并验证

### 6.1 开发期（源码检出）

把插件放到 `<cwd>/builtin/<id>@<version>/`，或设 `LANG_DIR=<你的根目录>`（`:`/`;` 分隔），
重启服务即可。`<cwd>/builtin` 是默认额外根，所以源码检出不需要先拷进 `~/.nolanguage`。

### 6.2 用户安装

首选 `nlg lang`（短动词，来源可以是**目录 / 压缩包 / URL / git 仓库**）：

```bash
nlg lang add /path/to/rust@1.0.0                        # 目录
nlg lang add ./rust.zip                                 # 或 .tar.gz / .tgz
nlg lang add https://example.org/rust.zip               # http(s) 归档
nlg lang add https://github.com/someone/nolang-rust.git # git 仓库（--depth 1）
nlg lang add <任意来源> --strict                         # 依赖不满足就直接拒绝，不落盘

nlg lang search [query]                                 # 浏览插件索引（文件/https 的静态 index.json）
nlg lang search lsp --source ./my-index.json            # 只用某个索引，--source 可重复
nlg lang add rust                                       # 裸 id 从索引解析成 downloadUrl 再装

nlg lang ls                                             # 版本/来源/是否启用/运行方式/扩展名
nlg lang info rust                                      # 单门语言全貌（含 requires 与来源）
nlg lang deps                                           # 依赖审计：谁要求什么、是否满足
nlg lang on rust | off rust                             # 启用 / 停用
nlg lang rm rust [--drop-data]                          # 卸载（默认保留 data/rust/）
nlg lang up rust                                        # 按记录的来源重装
```

**从索引安装**：`search` 与 `add <id>` 背后是 `src/langs/Catalog.ts`（详见《项目现状报告》§3.22）。一个索引就是一份静态 `index.json`（本地文件或 `https://` URL），列出每门语言的 `downloadUrl` + `sha256`；多份索引通过 `<home>/sources.json` 或 `--source` 共存，按 id 合并取最高版本。`add` 收到裸 id（不是路径 / URL / git）时，会自动从索引解析出 `downloadUrl` 再走来源归一化安装。无默认服务端，离线时 `search` 只打印提示、不报错退出。

来源归一化的两条保证：

- **归档里任何条目都不得逃出目标目录** —— `..`、绝对路径、盘符、软硬链接一律拒绝。
- **目录来源永不删除**：只有自己解包出来的临时目录才会被清理。

旧的 `lang-install` 入口仍然可用（两者共用同一个 `LanguageRegistry`）：

```bash
nlg run lang-install -- install /path/to/rust@1.0.0
nlg run lang-install -- list | disable rust | uninstall rust --drop-data | dir rust
```

`nlg`（Windows 上 `nlg.cmd`）是**转化层**：这个仓库直接跑源码 TS，每条命令都要
`--experimental-transform-types` 加自研的 `.js`→`.ts` resolver，`nlg run <script> -- <args>`
把这些收拢成一个短命令，`--` 之后的参数**原样透传**。等价的 npm 写法：
`npm run lang-install -- install <dir>`。

`--home <dir>` 指定插件根（默认 `$NOLANGUAGE_HOME`，否则 `~/.nolanguage`）。
坏 manifest 会让命令以退出码 1 失败并带上字段路径（`displayName: is required; …`），
不会装半个插件进去。

程序内安装与 UI 安装见下；二者与 CLI 共用同一个 `LanguageRegistry`。

```ts
const reg = new LanguageRegistry();          // home = ~/.nolanguage
await reg.scan();
await reg.install('/path/to/rust@1.0.0');    // → ~/.nolanguage/languages/rust@1.0.0
await reg.enable('rust');
```

卸载**默认保留** `~/.nolanguage/data/rust/`（断点、运行配置）；
要一起删传 `uninstall('rust', { keepData: false })`。
官方预装插件不可卸载，只能 `disable()`。

也可以用 UI：`http://127.0.0.1:7310/plugins`（或 IDE 的 Tools → Language Plugins），
填插件目录路径点 Install。安装/启停**不需要重启**，`applyRegistryChange()` 会就地增删 slot。

### 6.3 自检清单

1. **插件被扫到**：`GET /health` 或 `registry.describe()` 里能看到你的 `id`。
2. **校验通过**：`validateManifest(raw).ok === true`；失败时看 `issues[].field`。
3. **装配成功**：`new RunnerFactory(defaultRuntimeRegistry()).diagnose(manifest)` 返回 `ok: true`。
4. **能跑**：`workspace.run(id, code)` 返回 `exitCode: 0` 且 `stdout` 有内容。
5. **高亮生效**：打开对应扩展名的文件，状态栏语言显示你的 `displayName`。
6. **降级可读**：故意改坏 `discovery.commands`，状态栏应显示 `degradedNote` 而不是报错。
7. **Profile 可跑**：`workspace.status()` 之后 `profiler.supports(id) === true`；
   未知 adapter 会报 `ProfilerAdapterNotFoundError`，而不是悄悄跑成另一个语言。
8. **预算可算**：`workspace.resourceSummary().profiles` 里有你的一行，`memoryBytes > 0`。

### 6.4 参考实现

| 插件 | 运行时 | 值得抄的地方 |
|---|---|---|
| `builtin/python@1.0.0` | `repl-session` | `bootstrap.py` 的持久化契约（跳过函数/类/模块）、`debug` + `bundledFallback:"stub"` |
| `builtin/go@1.0.0` | `directory-session` | `scaffold` + `modes.test`、`delve` 的 debug 块 |
| `builtin/javascript@1.0.0` | `inline-vm` | 最小 `run` 块 |
| `builtin/markdown@1.0.0` | 无 | **不写 `run`** = 纯渲染语言，Run 自动禁用 |
| `examples/cpp@1.0.0` | `template` | **完整八面**：8 个扩展名、clangd、`g++/clang++` 发现、`modes.test`、codelldb；本机 g++ 16.1 实测编译运行 |

迁移脚本的完整可跑样例见 `scripts/verify-plugins.ts` 的 `testMigrations()`。

## 7. 常见错误

| 症状 | 原因 |
|---|---|
| `Runtime 'x' not available` | `run.mode` 拼错，或该运行时版本没装 |
| `Runtime requirement not met: template@^9.0.0` | `requires` 的区间超出已装版本 |
| `… requires X@^N, which this build does not provide` | `run.requires` 指向的是**宿主运行时**（`template` / `repl-session` / `directory-session` / `inline-vm` / `script-host`），它是本体的能力而不是可安装插件 —— 装不了，只能改 `requires` 的区间或用提供该运行时的构建。安装时就会报，`--strict` 下直接拒绝 |
| `nlg lang: no manifest.json in …` | 压缩包根目录没有 manifest；放进单层包装目录也会被自动下探，但路径要对 |
| `archive entry "…" would escape the destination` | 打包时把 `../` 或绝对路径打进去了，重新打包 |
| `Invalid run config: run.sourceExt is required` | 运行时契约没满足（各运行时的 `validate()` 会逐条说） |
| 插件在列表里但 `enabled: false` | `validateManifest` 没过——看 `installed()[i].validation.issues` |
| 高亮全没了 | 某条 `grammar.rules[].re` 编译失败（校验期就会拦，通常是被手动改坏了） |
| Run 报"documents render" | manifest 里没有 `run` 块 |
| `go test` 报找不到 go.mod | `scaffold.onFirstRun` 没写，或 `scaffold` 放错了层级（应在 **manifest 顶层**，不是 `run` 里） |
