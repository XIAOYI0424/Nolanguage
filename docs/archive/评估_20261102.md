## 三、项目评估

### 3.1 上次的 P0 解决了什么

| 上次的 P0 | 现状 | 证据 |
|---|---|---|
| `pycharm-client.ts` 4,196 行单模板字符串 | **已拆成 8 个 `.js` 分片**，模板字面量消失 | 拆分前后 `cmp` 字节一致（200,278 bytes）；5 条守卫 |
| 1606 条断言没有 CI | **CI 入库**，拆成 `pure`（约 2 分钟）+ `integration` | `.github/workflows/ci.yml`，`verify-all --pure` |
| 阶段 11 只有引擎没有落点 | **接进 `/perf`**：explain change + 判定卡片（p / Cohen's d / 变点） | `check-perf-html` 53/53 |

这三项是我上次判"最该先做"的，都做了，而且都留了可测的守卫。**这是这个项目最健康的地方：修一个问题会长出一条断言，而不是一段承诺。**

### 3.2 仍然存在的问题（按影响排序）

**P0 · 交付阻断**

1. **没有代码签名证书**。`nlg doctor` 如实显示 `signature NotSigned`。自签名链路是通的（`npm run sign -- -SelfSigned` 实测 Windows 认），但自签名不解决 SmartScreen——用户第一次双击仍然看到"Windows 已保护你的电脑"。**这是采购问题，不是工程问题**，但它决定了这个东西能不能给外人用。
2. **桌面壳押在 Edge 上**。Tauri 已正式搁置（`docs/Tauri搁置说明.md`）：本机 WebView2 运行时是 143、机器级安装、当前会话非管理员，两个安装器都返回 `0x80040828`；最小 wry 探针（20 行、无 IPC、无配置）同样渲染不出页面，证明**故障在环境**。现在窗口由 `msedge.exe --app` 打开——用户卸载 Edge 就没了。

**P1 · 结构**

3. **`server.ts` 仍有 1,424 行**。按域拆了 4 块（languages / migration / attribution / plugins），但 `main()` 里的 WS 分发仍是 900 行的单一 switch（63 个 case）。下一步该拆的是这个 switch，不是继续搬小函数。
4. **CI 只在 GitHub**。本机没有 pre-push 钩子，本地提交仍然可能带着红灯走。另外 `integration` 作业要临时 `npm i --no-save esbuild postject jsdom`——依赖的是"网上能装到"，与项目"零依赖"的哲学有点别扭（但这是构建期，可以接受）。
5. **依赖声明不实**：`@tauri-apps/plugin-dialog` 在 `dependencies` 里，全仓库 0 引用。"零第三方运行时依赖"目前靠"没人用它"成立，不靠清单。

**P2 · 一致性**

6. **文档落后四个版本**：`项目现状报告.md` 仍写 0.7.3 / 1598 / 35 套件，实际是 0.7.7 / 1729 / 37。这份文件是给外人看的"现状"，落后比没有更糟。
7. 空的 `dist/README.md`、`build/` 下两套 blob 并存（Nolanguage + ndebug），构建脚本各自硬编码 `C:\Users\15936\...` 的工具路径。

### 3.3 新引入的风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **两条发布链** | 现在有两个 exe 要构建、要冒烟、要签。构建时间从约 1 分钟变成约 2.5 分钟 | 已各自有套件；但还没有"一条命令出两个包"的脚本 |

| **Python agent 509 行无单测** | 只有端到端和"决策级对拍"覆盖 | 见 4.3 的建议 |

### 4.2 做对的五件事

1. **协议是"校验优先"的**：版本不符→致命断开，未知事件→丢弃继续，超长行→拒绝。这三条分别对应"不猜、不脆、不爆"。
2. **序列化不执行用户代码**：只读数据描述符、不调 `__repr__`/getter/`toString`、脱敏在序列化**之前**。这是"观测"和"改变程序"的分界线，也是唯一无法事后补救的一条。
3. **采样是固定成本**：不插桩，10 Hz 下 Python 实测开销可忽略；`effectiveHz` 报的是**实测值**而不是请求值——观测工具必须承认自己的真实开销。
4. **端到端测试用真进程**：`verify-ndebug` 起真的 `python app.py`，走真的 PYTHONPATH 注入、真的 TCP、真的 WebSocket，最后断言"页面加的 watch 拿到 3"。不是 mock。
5. **单入口 + 库分离**：`cli.ts` 只做参数和生命周期，`main.ts` 是纯库，SEA 打包不需要 `import.meta.url` 的赌博。

### 4.3 缺陷（这一节是评估的重点）

**已修（本轮，均有断言）**

| # | 缺陷 | 后果 | 修法 | 断言 |
|---|---|---|---|---|
| 1 | **遮蔽用户的 `sitecustomize`** | 用户环境里已有的 hook（coverage.py、公司 bootstrap）**静默失效**——几周后才发现"覆盖率不采了" | 我们的 sitecustomize 在 boot 后主动链式加载被遮蔽的那个 | `app: a pre-existing sitecustomize still runs` |
| 2 | **stdin 被 `ignore`** | 程序里 `input()` 立刻 `EOFError`——**附加观测改变了程序行为** | `stdio: ['inherit','pipe','pipe']` | 手动验证（无自动化，见下） |
| 3 | **端口占用时泄漏子进程** | `ndebug app.py` 在 7320 被占时，报错退出但**目标程序还在跑**、临时 agent 目录也不删 | `ws.listen()` 失败时 kill 子进程 + 关 session + 删目录 | `app: a busy port is reported` + 首个实例仍存活 |
| 4 | **工作线程崩溃不可见** | `sys.excepthook` 只管主线程；worker 线程挂了什么都不显示——**恰恰是用户最想查的场景** | 安装 `threading.excepthook` | 代码路径（e2e 未覆盖） |
| 5 | **`--hz 0` 静默变成 10** | `Number(x) \|\| 10` 把 0 当假值，用户指定的采样率被无声替换 | 解析后显式校验范围 | `cli: an out-of-range hz is refused` |
| 6 | 页面页脚显示请求端口而非实际绑定端口 | `--port 0` 时页脚显示 `:0`（功能不受影响，因为 WS 用 `location.host`） | 改为延迟渲染、用 bound port | 代码路径 |

**未解（按我判断的严重度）**

1. **双实现漂移（最重要）**。`serializer.ts` 和 `nlg_agent.py` 是两份手写实现。我加了"决策级对拍"（8 条：redact / cycle / item cap / more / depth / 三个限额），但这只证明**这几个决策**一致，不证明形状一致。已经暴露的差异：Python 的 `dict` 序列化成 `map`，JS 的普通对象是 `obj`——同一个概念两种节点。**这是设计选择，但必须写进契约文档**，否则下一个人会以为是 bug。
2. **Python agent 459 行没有单测**。所有覆盖都来自端到端（33 条里的 8 条）和对拍（8 条）。`ser()` 的分支很多（dict/list/set/tuple/`__slots__`/`__dict__`/安全类型/未知类型），e2e 只走到 2–3 个分支。**建议**：把 `ser` 抽成纯函数模块，用 `python -m unittest` 或让 vitest 通过子进程喂用例（项目已有 `spawnSync` 先例）。
3. **单连接设计**：`session.ts:145` 在 `state !== 'listening'` 时直接 `destroy()`。好处是不会多路复用混乱；代价是 **multiprocessing / fork 出来的子进程连不上**，而且子进程里的 agent 会静默失败（`sitecustomize` 里 catch 了）。这类程序在 ndebug 下"只有父进程可见"，界面上看不出来。
4. **没有 pause**：10 Hz 刷新的界面在排查时很晃。缺一个"冻结当前视图"的按钮（纯前端，10 行）。
5. **没有快照 diff**：设计里的 M2 项。目前两次快照只能人工比对。
6. **`_namespace()` 每 tick 复制 12 帧的全部局部变量**：一个局部变量很多的函数（比如加载了大字典的 `main`）会让 2 Hz 的 locals 采样变成"复制大对象"。引用复制不贵，但 `list(f.f_locals.items())` 在极端情况下会有可见开销。**建议**：只对最内层 3 帧做完整合并，更外层只按名字取 watch 需要的键。

**安全复核（结论：可接受，但边界要说清）**

- 只监听回环 + 32 hex 一次性 token + 单连接 → 同机其它进程要连需要先知道端口和 token（端口在 1024–65535 随机，token 32 hex）。可接受。
- 序列化不执行代码、脱敏在进程内 → 可接受。
- **watch 表达式是 `eval`**：这是设计决定的"用户信任模型"——用户输入的表达式会在目标进程里执行。文档写明了，但界面上没有提示。**建议**：Watch 输入框旁加一句"表达式会在目标进程中执行"（成本 1 行，收益是避免有人写 `os.system(...)` 才发现）。

## 五、建议（按 ROI 排序）

**先做（半天内，收益立竿见影）**

1. **给 Watch 输入加"会在目标进程执行"的提示**——1 行 HTML，避免一次误用。
2. **加 pause（冻结视图）**——纯前端，10 行，解决 10 Hz 晃眼。
3. **把 `项目现状报告.md` 更新到 0.7.7**——它现在是给外人看的门面，落后四个版本。

**再做（1–2 天）**

4. **Python agent 的单测**：把 `ser()` 抽成独立模块，喂 20 个用例（dict/list/set/`__slots__`/安全类型/未知类型/深度/环/脱敏），与 TS 侧对拍扩展成"形状级"而非"决策级"。
5. **多进程可见性**：要么允许多连接（每个 pid 一个 view，界面加一个进程选择器），要么在界面上明确写"只观测主进程"。
6. **`server.ts` 的 switch 拆分**：按域（exec / debug / fs / plugins / perf）搬出 `main()`，这是 IDE 侧最后一块 900 行的东西。

**交付链（需要外部条件）**

7. **签名证书**：拿到 `.pfx` 后一条命令（脚本已就绪）。
8. **WebView2 运行时升级后复测 Tauri**：一次性实验，决定"继续投"还是"彻底砍"。现在是搁置状态，代码还在维护成本里。
9. **一条命令出两个包**：`npm run build:all` = exe + setup + ndebug，避免两条链不同步。
