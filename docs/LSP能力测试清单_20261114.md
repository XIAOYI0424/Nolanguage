# LSP 导航能力测试清单（跳转定义 / 查找引用 / 符号重命名 / 快速修复 / 全局符号搜索）

日期：2026-11-14 · 版本 0.7.23 · 状态：**协议层与客户端已实现（2026-11-15），UI 绑定与其余语言的服务未做**

**本清单不区分语言优先级。** 五项能力是一份**契约**：由每个语言插件的 manifest 声明自己是否提供，客户端、面板、测试只读声明，不认语言名。任何一处出现 `if (language === 'python')` 都是缺陷。

---

## 零、缺口的正确切法

一个常见误判是「装上 pyright 就有了」。实际不是，但也不该按「Python 缺什么」来组织——那会把一份通用契约写成某个语言的待办。真实缺口是四层，**每层都与语言无关**：

| 层 | 现状 | 证据 |
|---|---|---|
| ① 能力声明 | ⚠️ 不用 manifest 声明，改由**服务端 `initialize` 结果**决定 | 见下方「2026-11-15 实现说明」——服务端声明比 manifest 副本更准，避免两处真相 |
| ② LSP 客户端 | ✅ **已实现 5 个请求** | `src/lsp/navigation.ts` + `LspClient.definition/references/renameSymbol/codeActions/workspaceSymbols` |
| ③ 面板协议 | ✅ **5 个结果帧已加**（带 `unsupported` 字段） | `src/panel/PanelHub.ts` + `src/panel/handlers/navigation.ts` |
| ④ 降级说明 | ✅ 做好，且**语言中立** | 服务端没装 → `degradedNote`；服务端不实现 → `unsupported: "<server> does not implement <method>"` |
| ⑤ 客户端 UI 绑定 | ✅ **已做** | `src/ui/client/68-nav.js`：五个按键 + Ctrl+单击 + 结果浮层；`verify-ui-dom` 7 条断言覆盖 |
| ⑥ 其余语言的服务 | ❌ 依赖用户安装 | gopls / tsserver / marksman 都支持这些方法，装上即生效 |

### 2026-11-15 实现说明

协议层与客户端已完成，并且**内置 Python 服务（`src/python/pyrightServer.py`）用 `ast` 实现了全部五个方法**（同文件范围），所以不装 pyright 也能用：

| 能力 | 实测（打包 exe，端到端） |
|---|---|
| 跳转定义 | `add(...)` → 1 处，line 0 col 4 |
| 查找引用 | 2 处（定义 + 调用） |
| 符号重命名 | `add`→`sum2` 2 处编辑；`2bad` 被拒（`the server cannot rename this symbol`） |
| 快速修复 | `import os` 未使用 → `Remove unused import 'os'` |
| 全局符号 | 查询 `ad` → `add:function` |

**一个设计修正**：清单原本打算用 manifest 的 `lsp.capabilities` 做声明。实现时改为读服务端 `initialize` 返回的 `*Provider` 字段——那才是权威来源，manifest 再写一份只会造出第二处真相（这正是本项目这一周在清理的问题）。

**客户端已接上**（2026-11-15 补）：`Ctrl+B` 跳转定义、`Alt+F7` 查找引用、`Shift+F6` 符号重命名（项目树里仍是文件重命名，按焦点分区）、`Alt+Enter` 快速修复、`Ctrl+T` 全局符号，另有 `Ctrl+单击` 跳转。结果用键盘可导航的浮层展示；`unsupported` 走对话框而不是空列表。

**仍未做**：其余语言的服务需用户自行安装（装上即可用，因为请求已经是通用的）。

第 ① 层缺失是最要命的一环：**没有声明，UI 就只能靠语言名硬编码来决定要不要显示「跳转定义」**。补上它，后面三层全部退化成通用逻辑。

### 契约形状（建议）

```jsonc
// builtin/<lang>/manifest.json
"lsp": {
  "discovery": { "commands": ["gopls"] },
  "command": ["{resolved}"],
  "serverName": "gopls",
  "degradedNote": "gopls not installed — Run works, Check and completion do not",
  // 新增：本插件承诺支持的请求。缺省 = 全部不支持（保守默认）。
  "capabilities": ["definition", "references", "rename", "codeAction", "workspaceSymbol"]
}
```

判定规则（**任何语言同一条**）：

| 情形 | 行为 |
|---|---|
| manifest 未声明该能力 | UI 隐藏入口；请求返回 `{ unsupported: true, reason: 'not declared by <lang>' }` |
| 声明了，但服务端返回 `MethodNotFound` | `{ unsupported: true, reason: 'server does not implement' }`，首次遇到时记一条日志 |
| 服务端没装（discovery 失败） | 返回 `degradedNote` 原文，UI 显示提示而非错误框 |
| 声明了、服务端也支持 | 正常结果 |

## 一、逐能力验收标准（与语言无关）

### 1. 跳转定义 `textDocument/definition`

| 项 | 内容 |
|---|---|
| 请求帧 | `{ kind: 'definition', language, code, line, character, requestId }` |
| 响应帧 | `{ kind: 'definitionResult', requestId, locations: [{ uri, line, character }], unsupported? }` |
| UI 触发 | `Ctrl+单击`；`Ctrl+B` |
| 验收 | ① 单一定义跳准；② 多处定义返回全部；③ 跨文件；④ 内置/外部符号返回空而非 error 帧；⑤ 未知符号返回空数组；⑥ 未声明能力的语言返回 `unsupported` 且**不弹错误框** |

### 2. 查找引用 `textDocument/references`

| 项 | 内容 |
|---|---|
| 请求帧 | `{ kind: 'references', language, code, line, character, includeDeclaration }` |
| 响应帧 | `{ kind: 'referencesResult', requestId, locations: [...], truncated? }` |
| UI 触发 | `Alt+F7`，结果显示在底部面板 |
| 验收 | ① 计数与人工核对一致；② `includeDeclaration` 真假各测；③ 跨文件；④ 注释/字符串里的同名不算；⑤ 超上限必须带 `truncated`，不能静默截断 |

### 3. 符号重命名 `textDocument/rename`

| 项 | 内容 |
|---|---|
| 请求帧 | `{ kind: 'renameSymbol', language, code, line, character, newName }` |
| 响应帧 | `{ kind: 'workspaceEdit', requestId, edits: [{ uri, range, newText }] }` |
| UI 触发 | 编辑器内 `Shift+F6`；项目树内 `Shift+F6` 仍是**文件**重命名（按焦点分区） |
| 验收 | ① 定义与所有引用一起改；② 字符串/注释**不改**；③ 非法新名（`2bad`、关键字）被拒并给原因；④ 与既有符号冲突时警告；⑤ 内置符号拒绝；⑥ 跨文件；⑦ 改名后不产生新诊断；⑧ 未声明能力的语言（如 Markdown）明确拒绝 |

> ⚠️ `Shift+F6` 现在绑给项目树文件重命名（`{ label: 'Rename…', sc: 'Shift+F6', act: startInlineRename }`）。不按焦点分区就绑符号重命名，会出现「想改符号结果改了文件名」——数据事故级。

### 4. 快速修复 `textDocument/codeAction`

| 项 | 内容 |
|---|---|
| 请求帧 | `{ kind: 'codeAction', language, code, line, character, diagnostics }` |
| 响应帧 | `{ kind: 'codeActionResult', requestId, actions: [{ title, kind, edit }] }` |
| UI 触发 | 光标停在诊断处按 `Alt+Enter`；灯泡图标 |
| 验收 | ① 有可用修复时返回非空；② 无可用修复返回空数组；③ 应用 edit 后诊断消失；④ `kind` 可用于分组（`quickfix` / `source.organizeImports`）；⑤ 未声明能力时 `unsupported` |

### 5. 全局符号搜索 `workspace/symbol`

| 项 | 内容 |
|---|---|
| 请求帧 | `{ kind: 'workspaceSymbol', language?, query }` |
| 响应帧 | `{ kind: 'workspaceSymbolResult', requestId, symbols: [{ name, kind, uri, line }], truncated? }` |
| UI 触发 | `Ctrl+Alt+Shift+N` 或 `Ctrl+T` |
| 验收 | ① 跨文件；② 模糊匹配（`ad` 命中 `add`）；③ 空查询行为写进文档（返回上限内全部，或空数组，二选一）；④ 带文件+行号可跳转；⑤ 大仓库 < 2 s；⑥ `language` 省略时按「所有声明了该能力的插件」聚合 |

## 二、语言矩阵（每行同权，同列同判）

「声明」= manifest `lsp.capabilities` 应包含它；「服务」= 该语言选定的 LSP 是否真提供。**本机四个服务都没装，服务列来自各自文档，未实测**——落地时每格都要用第三节用例跑一遍。

| 语言 | 选定服务 | 定义 | 引用 | 重命名 | 快速修复 | 全局符号 |
|---|---|---|---|---|---|---|
| Python | pyright | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ |
| JavaScript/TypeScript | typescript-language-server | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ |
| Go | gopls | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ | 声明✅ 服务✅ |
| Markdown | marksman | 声明✅ 服务✅（链接/标题） | 声明✅ 服务✅（反向链接） | 声明❌ 服务❌ | 声明❌ 服务❌ | 声明✅ 服务✅（标题） |
| 任意新插件 | 自带 | 由 manifest 决定 | 同左 | 同左 | 同左 | 同左 |

**没有「基准语言」。** 测试矩阵对每种语言跑同一套编号用例；Markdown 的 `N6/N7/N8/N9` 记为 `N/A`（manifest 未声明），而不是「未实现」。

### 内置兜底：不是 Python 专属

`pyrightServer.py` 是 Python 的兜底实现，但**兜底机制本身是通用的**：任何插件都可以在自己的 `lsp` 块里声明 `bundledFallback`，只要满足同一套帧与判定规则。当前只有 Python 有（`"bundledFallback": "stub"`），这不是设计特权，只是它先做了。

基于 AST 的同文件实现（定义/引用/重命名/符号搜索）对**任何**有语法树的语言都成立；跨文件需要索引，成本高但可后置。

## 三、可执行用例（编号统一，逐语言跑同一套）

下表是**通用**用例，对每个语言都跑一遍，`<ext>` 换成该语言扩展名。fixture 用该语言的等价写法，语义与期望完全一致。

| # | 能力 | fixture 语义 | 期望 |
|---|---|---|---|
| N1 | 定义 | 定义函数 `F`，另一行调用 `F` | 跳到定义所在行 |
| N2 | 定义-跨文件 | `a.<ext>` 定义 `F`，`b.<ext>` 调用 | 跳到 `a.<ext>` |
| N3 | 定义-未知符号 | 光标在 `no_such_thing` 上 | 空数组，无 error 帧 |
| N4 | 引用 | `F` 有 2 处调用 | `includeDeclaration:true` → 3；`false` → 2 |
| N5 | 引用-排除注释 | 注释里出现同名 `F` | 不计入 |
| N6 | 重命名 | `F` → `G` | 定义+2 调用全改；字符串 `"F"` 不变 |
| N7 | 重命名-非法名 | 改成该语言的关键字 | 拒绝 + 原因 |
| N8 | 重命名-内置符号 | `print` / `fmt.Println` / `console.log` | 拒绝 |
| N9 | 快速修复 | 该语言最典型的一条可修诊断 | 返回 ≥1 个 action，应用后诊断消失 |
| N10 | 快速修复-无可用 | 干净代码 | 空数组 |
| N11 | 全局符号 | 查询 `F` | 返回 `F`，带 uri+line |
| N12 | 全局符号-模糊 | 查询 `F` 的前两个字母 | 命中 |
| N13 | 未声明能力 | 对未声明该能力的语言发请求 | `unsupported: true`，无错误框 |
| N14 | 服务未安装 | 把该语言 discovery 指到不存在的命令 | 返回 `degradedNote` 原文 |
| N15 | 请求超时 | 服务端人为不响应 | ≤5 s 返回 error 帧，UI 可重试 |

各语言的等价 fixture：

| 语义 | Python | Go | JavaScript | Markdown |
|---|---|---|---|---|
| 定义/调用 | `def F(a): return a` | `func F(a int) int` | `function F(a){return a}` | `# 标题` + `[链](#标题)` |
| 典型可修诊断 | 未使用 import | 未使用 import | 未使用变量 | 断链 |
| 内置符号 | `print` | `fmt.Println` | `console.log` | —（N8 记 N/A） |

## 四、落地顺序（按层，不按语言）

1. **manifest 契约**：加 `lsp.capabilities`（含校验：只允许已知方法名，未知值报错）。四个内置插件按实际填。
2. **协议 + 客户端**：五个请求/响应，复用现有 `requestId`；`MethodNotFound` 映射为 `unsupported`。
3. **UI**：入口按 `capabilities` 显隐；`Shift+F6` 按焦点分区；结果面板。
4. **测试套件** `scripts/verify-lsp-nav.ts`：对**每个**声明了能力的插件跑 N1–N15；对未声明的跑 N13/N14。接进 `verify-all`。
5. **兜底实现**（可选，推荐）：给需要它的插件补同文件 AST 实现——按插件逐个开，不是给「Python」开。

**验收口径**：每种语言的每格都要有自动化断言；`N/A` 必须是「manifest 未声明」，不是「跑失败了懒得修」。

## 五、防止回退

`verify:arch` 的词汇规则（R3）应扩展一条：**`src/panel` / `src/lsp` 里不得出现语言名字面量**，语言相关的一切走 manifest。这条比任何文档都更能防止「顺手给某个语言加个特判」。

但**现在还不能直接上这条规则**——先量了一下，`src/panel` + `src/lsp` 里现有 **49 处**：

| 语言 | 处数 | 典型位置 |
|---|---|---|
| python | 25 | `coverage.ts:80` 直接写死 `const language = 'python'` |
| go | 9 | 扩展名映射、默认命令 |
| javascript | 9 | 同上 |
| markdown | 6 | 同上 |

其中一部分是「扩展名 → 语言 id」的映射表（`FsService.ts: py: 'python'`），本应由 manifest 的 `file.extensions` 生成；另一部分是真·硬编码（`coverage.ts` 的 `const language = 'python'`）。

所以顺序是：**先把数据搬进 manifest → 再收紧预算 → 才谈给五种能力写特判**。否则新能力一落地，就会顺着现有硬编码路径再长出一批。

**2026-11-14 更新**：这条已经落成门禁 `scripts/verify-langparity.ts`（接入 `verify-all`），用 **ratchet** 而不是一刀切：

- 「不得按语言名比较」是**硬规则**，现在 0 处违规——写门禁时顺手修了两处真硬编码：`perf.ts` 的 `language !== 'python'`（改成读 manifest 的 `run.coverage`）、`interpreters.ts` 的 `` `${languageId === 'python' ? 'Python ' : ''}` ``（列表本就按语言分组，去掉前缀）。
- 裸字面量按**每文件预算**卡住（当前 49 处，总数与分文件数都写在脚本里），只允许下降，新增即失败。
- 本清单可直接落成 `scripts/verify-lsp-nav.ts`，纯 WS 驱动，不需要打包 exe。
