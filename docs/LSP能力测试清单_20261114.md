# LSP 导航能力测试清单（跳转定义 / 查找引用 / 符号重命名 / 快速修复 / 全局符号搜索）

日期：2026-11-14 · 版本 0.7.23 · 状态：**清单（未实现）**

本文只回答一个问题：**这五项能力要能验收，需要测什么、按什么标准判过。**

---

## 零、先看清缺口在哪一层

一个常见误判是「装上 pyright 就有了」。实际不是——这五项在**四层里缺三层**：

| 层 | 现状 | 证据 |
|---|---|---|
| ① LSP 客户端 | **只实现 3 个请求**：`completion` / `hover` / `diagnostic` | `grep "'textDocument/" src/lsp/*.ts` 仅这 3 个 + `didOpen`/`didChange`/`publishDiagnostics`/`workspace/configuration` |
| ② 面板协议 + UI | **没有对应帧**，也没有按键绑定（`Shift+F6` 现在绑给项目树的**文件**重命名） | `src/panel/PanelHub.ts` 的出站 kind 列表里无 definition/references/rename/codeAction/symbol |
| ③ 语言服务端 | 内置 Python 服务只处理 `initialize`/`didOpen`/`didChange`/`didClose`/`completion`/`hover`/`diagnostic` | `src/python/pyrightServer.py` 第 122–183 行 |
| ④ 降级说明 | ✅ **已做好**（唯一达标的一层） | `check` 回复带 `note="gopls not installed — Run works, Check and completion do not"` |

所以验收清单必须按层写：**客户端能发 → 面板能收 → UI 能显示 → 无服务时能说清**。

## 一、逐能力验收标准

### 1. 跳转定义 `textDocument/definition`

| 项 | 内容 |
|---|---|
| UI 触发 | `Ctrl+单击` 符号；`Ctrl+B`（PyCharm 同键） |
| 请求帧 | `{ kind: 'definition', code, language, line, character, requestId }` |
| 响应帧 | `{ kind: 'definitionResult', requestId, locations: [{ uri, line, character }] }` |
| 验收 | ① 单一定义跳准；② 多处定义（同名重载/条件定义）返回全部；③ 跨文件跳转；④ 内置符号（`print`）返回空而非报错；⑤ 未知符号返回空数组（**不是** error 帧） |

### 2. 查找引用 `textDocument/references`

| 项 | 内容 |
|---|---|
| UI 触发 | `Alt+F7`（PyCharm 同键），结果显示在底部面板 |
| 请求帧 | `{ kind: 'references', code, language, line, character, includeDeclaration: true }` |
| 响应帧 | `{ kind: 'referencesResult', requestId, locations: [...], truncated?: boolean }` |
| 验收 | ① 计数与人工核对一致；② `includeDeclaration` 真假两种都测；③ 跨文件；④ 字符串/注释里的同名不算引用；⑤ 结果超过上限时有 `truncated` 标记（不能静默截断） |

### 3. 符号重命名 `textDocument/rename`

| 项 | 内容 |
|---|---|
| UI 触发 | 编辑器内 `Shift+F6`；项目树内 `Shift+F6` 仍是**文件**重命名（上下文区分，与 PyCharm 一致） |
| 请求帧 | `{ kind: 'renameSymbol', code, language, line, character, newName }` |
| 响应帧 | `{ kind: 'workspaceEdit', requestId, edits: [{ uri, range, newText }] }` |
| 验收 | ① 定义与所有引用一起改；② 字符串字面量、注释**不改**；③ 非法新名（`2bad`、关键字 `class`）被拒并给原因；④ 与既有符号冲突时警告；⑤ 内置符号（`print`）拒绝；⑥ 跨文件改名；⑦ 改名后诊断不出现新错误 |

> ⚠️ 现状冲突：`Shift+F6` 已绑给项目树的文件重命名（`{ label: 'Rename…', sc: 'Shift+F6', act: startInlineRename }`）。落地时必须按焦点分区，否则「在编辑器里按 Shift+F6 却改了文件名」是数据事故级体验。

### 4. 快速修复 `textDocument/codeAction`

| 项 | 内容 |
|---|---|
| UI 触发 | 光标停在诊断处按 `Alt+Enter`；灯泡图标 |
| 请求帧 | `{ kind: 'codeAction', code, language, line, character, diagnostics: [...] }` |
| 响应帧 | `{ kind: 'codeActionResult', requestId, actions: [{ title, kind, edit }] }` |
| 验收 | ① 未定义名 → 「添加 import」；② 未使用 import → 「移除」；③ 无可用修复时返回空数组；④ 应用 edit 后诊断消失；⑤ `kind` 字段可用于分组（`quickfix` / `source.organizeImports`） |

### 5. 全局符号搜索 `workspace/symbol`

| 项 | 内容 |
|---|---|
| UI 触发 | `Ctrl+Alt+Shift+N`（PyCharm 同键）或 `Ctrl+T` |
| 请求帧 | `{ kind: 'workspaceSymbol', query }` |
| 响应帧 | `{ kind: 'workspaceSymbolResult', requestId, symbols: [{ name, kind, uri, line }], truncated? }` |
| 验收 | ① 跨文件返回；② 模糊匹配（`ad` 命中 `add`）；③ 空查询的行为明确（返回上限内全部，或空数组，二选一并写进文档）；④ 结果带文件+行号，可点击跳转；⑤ 大仓库下响应 < 2 s |

## 二、语言 × 能力矩阵

`✅ 支持` / `⚠️ 部分` / `❌ 不支持` / `— 不适用`。「提供者」指该语言该能力由谁实现。

| 语言 | 提供者 | 定义 | 引用 | 重命名 | 快速修复 | 全局符号 |
|---|---|---|---|---|---|---|
| **Python** | pyright（需安装） | ✅ | ✅ | ✅ | ✅ | ✅ |
| Python（内置兜底） | `pyrightServer.py` | ❌ | ❌ | ❌ | ❌ | ❌ |
| **JavaScript/TypeScript** | typescript-language-server | ✅ | ✅ | ✅ | ✅ | ✅ |
| **Go** | gopls | ✅ | ✅ | ✅ | ✅ | ✅ |
| **Markdown** | marksman | ✅（链接/标题） | ✅（反向链接） | ❌ | ❌ | ✅（标题） |
| **zh-cn**（本地化包） | — | — | — | — | — | — |

**证据说明**：第一列（本产品的缺口）是本次实测/读码确认的；第二列的 ✅/⚠️/❌ 来自各语言服务**自身文档声明**的能力——本机没装 pyright / tsserver / gopls / marksman，无法实测。落地时每一格都要用第三节的用例真跑一遍再改成实测结论。

**兜底路线值得单独考虑**：产品已有「没有真 LSP 就用内置实现」的先例。`pyrightServer.py` 基于 `ast`，完全可以做**同文件内**的定义/引用/重命名/符号搜索（跨文件需要索引，代价高）。这比「什么都没有」强得多，且不增加依赖。

## 四、落地顺序（建议）

1. **客户端 + 协议层**（前置，无它则一切免谈）：`definition` / `references` / `rename` / `codeAction` / `workspaceSymbol` 五个请求 + 响应路由，复用现有 `requestId` 机制。
2. **Python（真 pyright）**：五个能力一次到位，作为验收基准。
3. **内置兜底的同文件实现**：`ast` 可覆盖定义/引用/重命名/符号搜索，保证「没装 pyright 也不至于完全不能跳」。
4. **Go / JS**：接 gopls / tsserver，主要是配置与 note 文案。
5. **Markdown**：只做定义 + 全局符号（标题），重命名明确不支持。
6. **UI 收尾**：`Shift+F6` 按焦点分区、`Alt+Enter` 灯泡、结果面板。

---

## 五、验收口径

- 每格「✅」必须有一条**自动化断言**，不接受人工目测。
- 降级路径（D1–D3）与功能路径**同等重要**：现在的 `note` 文案是产品里少有的「诚实设计」，新能力不能破坏这个约定。
- 本清单可直接落成 `scripts/verify-lsp-nav.ts`，接进 `verify-all`（`requiresExe` 可省，纯 WS 驱动）。
