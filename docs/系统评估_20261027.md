# Nolanguage 系统评估

> 评估对象：0.7.4（`e69226c`，2026-10-27）  
> 评估方式：读代码 + 实测（构建、启动、内存、全量套件），不采信文档里的自我描述  
> 评估人：老婆

---

## 一、结论先说

**这是一个工程纪律明显高于平均水平、但仍在收敛期的系统。**

- 架构判断是对的：三总线 + 两脊柱 + 语言插件化 + 五种通用运行时，边界干净，语言逻辑真的没有漏回引擎（有 grep 断言守着）。
- 验证是这套系统最强的资产：35 个套件、1606 条断言，而且大量断言测的是**"会不会骗人"**（未签名 vs 目录签名、`/health` 有响应 ≠ 同一个构建、CUSUM 在平坦序列上必须沉默）。
- 最大的问题不在架构，在**两处巨型文件**和**交付链最后一百米**（无签名证书、Tauri 不可用）。

综合评分：**7.6 / 10**（详见第七节）。

## 三、架构：判断是对的

**做得好的地方（不是客套，是有证据的）：**

1. **可观测性是骨架，不是外挂。** `Kernel` 的三条总线（commands/events/services）自动埋点，任何命令都自带 span、耗时、traceId、gitCommit。这不是"加了个日志"，是"结构上不可能观测不到"。

2. **插件化是真的，不是配置文件装样子。** 判定方式很硬：`grep -nE "=== *'(python|go|javascript|markdown)'" src/runtimes src/langs src/panel/WorkspaceService.ts` 必须为空——现在是空的。`RunnerFactory.create(manifest)` 是唯一装配点，五种运行时（template/repl-session/directory-session/inline-vm/script-host）是通用能力，不是按语言写的 runner。

3. **诊断链路完整。** `doctor` 五态（ok / not-running / orphan-server / port-conflict / window-missing）+ 启动版本握手（同构建复用 / 无窗口接管 / 异构建替换）+ 安装回执 + 签名状态。这条链是我在别的同类项目里最少见到的部分。

4. **零第三方运行时依赖是硬约束，且守住了。** 自研 WS、JSON-RPC、LSP/DAP 帧、Markdown 渲染、XML 解析。代价是代码量，收益是没有供应链风险、没有版本地狱。

5. **迁移门槛落到了"可用"而不是"看起来像"。** 解释器识别会真的读 `pyvenv.cfg` 校验 venv、读 `.idea/misc.xml` 的 SDK 名；`.idea` 导入会把 `$PROJECT_DIR$` 展开、把 `default="true"` 模板跳过、把重名和无脚本项记成 warning 而不是静默吞掉。

## 四、风险清单

### P0 — 会直接伤到用户或交付

**1. `pycharm-client.ts` 4,196 行是一个模板字符串**

整个前端是 `return \`...\`` 一个字符串。里面任何一个反引号（哪怕在注释里）都会把模板截断，而 tsc 的报错位置在几十行之后，现象是"页面只跑了一半脚本"或"服务器起不来"。

**这不是理论风险：0.7.2 和 0.7.4 各踩了一次**（都是我写的注释里带了反引号）。已加守卫（`verify-pycharm`: 模板区间内不得出现反引号），但结构本身没变——守卫只能防这一类，防不了 `${` 插值、防不了文件继续膨胀。

**2. 没有代码签名证书**

`nlg doctor` 现在会明说 `signature NotSigned`。自签名链路是通的（`npm run sign -- -SelfSigned`，实测 Windows 认），但自签名**不解决 SmartScreen**——用户第一次双击仍会看到"Windows 已保护你的电脑"。这不是技术问题，是采购问题。

**3. Tauri 壳不可用**

`tauri-shell.log` 明确记录 `page-load never finished within 20s`，没有 `msedgewebview2` 宿主进程、没有 crash dump。当前桌面形态是 **Edge `--app`**——意味着用户装了 Edge 才能用，Edge 被卸载/大版本更新都可能影响。

顺带修了一个会误导判断的诊断 bug：`webView2Version()` 之前读的是 Edge 的 `EdgeCore`（151），而嵌入式应用真正加载的 **Evergreen Runtime 是 143**。查了一整轮才发现版本号是假的。

### P1 — 质量与可维护性

**4. `server.ts` 1,810 行 / 63 个 WS case**

路由、handler、装配、插件页 payload、doctor 辅助函数都在这一个文件里。handler 已经抽成独立函数了（搬迁成本低），但文件本身已经超出"一眼能看完"的规模。

**5. 启动 3.4s（暖）/ 5.4s（冷）**

桌面应用感知明显。分解看：**进程 + SEA 模块加载 ~1.7s 是大头**（92MB 单文件 + 全量 TS 打包），扩展宿主 0.36s，LSP `initialize` 0.66s（这条还被自己记成了 `Slow RPC roundtrip`，阈值 60ms）。

**6. 单测只有 113 行**

纯逻辑现在主要靠脚本套件验证，跑一次全量要 3 分钟、粒度粗。`Attribution`、`interpreters`、`xml` 这些纯函数完全适合 vitest 秒级反馈，现在却只在慢套件里跑。

**7. CI 配置不在仓库**

`.github/workflows/ci.yml` 在 `.gitignore` 里。一个维护着 1606 条断言的项目，没有推送即回归，这套资产的折旧速度会比想象中快。（同批被忽略的还有 `.gitignore` 自己、`.cargo/config.toml`——像是历史遗留的误加。）

**8. 阶段 11 只有引擎，没有落点**

`attribute()` + WS `attribute` 命令都通了，但 `/perf` 页面没有入口，只有 Tools 菜单弹一个模态框。归因的价值在"看见趋势 + 知道是哪次变更"，现在只完成了前半句。

### P2 — 细节

9. `@tauri-apps/plugin-dialog` 声明在 `dependencies` 但**全仓库 0 引用**——"零第三方运行时依赖"这句话目前靠"没人用它"成立，不靠清单。
10. 空闲 5 进程 / 262MB：2 个 `python.exe` 常驻（LSP + profiler 探测）、1 个 `node.exe` 沙箱。
11. 63 个 server case vs 61 个 client case，有 2 个协议方法没有对端，建议对账（死协议比死代码更难发现）。
12. 注释与文案有过时描述（已修一处：Run/Debug 配置对话框写"驱动 Run 和 Debug"，实际 Run 跟的是当前文件）。

## 五、这轮体检修掉的真实 bug

评估不只是打分，顺手修了 4 个会静默出错的问题（0.7.4）：

| 问题 | 后果 | 修法 |
|---|---|---|
| `.idea` 导入存 `params`/`workdir`，运行/调试读 `args`/`cwd` | **导入成功但参数和工作目录被丢弃**——最典型的"看起来迁移了其实没迁" | 存 `args`/`cwd`，并加引号感知的 `splitArgs`（`--data "C:/My Data"` 不再被拆碎） |
| 调试 `cwd` 直接透传给 DAP | `.idea` 的 `$PROJECT_DIR$/src` 变成相对路径，适配器指向不存在的目录 | 服务端按 `workspace.root` 解析 |
| `tests/phase1.test.ts` 在 `.gitignore` 里 | **新克隆跑 `npm test` 没有测试** | 移出忽略并入库（+`docs/`、`.workbuddy-ai/` 加入忽略） |
| 死代码 `ideaImport.isDirectory`、`xml.byAttr`；`clearEmbeddedSignature` 无测试 | 无消费者 / 与 `build-exe` 内联实现可能漂移 | 删除死代码；给 `clearEmbeddedSignature` 补真实文件测试 |

另外新增一条**回归守卫**：模板内不得出现反引号（同类事故已两次）。

修完复验：`tsc` 0 错误，全量 **1606/1606 · 35 套件**，`npm test` 9/9。

## 六、给下一步的排序（按 ROI）

1. **拆 `pycharm-client.ts`**（最高优先，成本最低收益最大）。文件里已经有 `// ---------- sections ----------` 分区，按分区切 6–8 个模块，用现有 `?raw` 机制拼接注入即可，不需要重构逻辑。这一步能把"注释里一个反引号搞崩整页"的概率降到接近 0。
2. **CI 入库 + 分片跑套件**：纯逻辑套件（attribution/migration/handshake/doctor/xml）秒级先跑，需要 exe 的套件放后面。1606 条断言不该只存在于本机。
3. **更新 WebView2 Evergreen Runtime 再测 Tauri**：一次性实验，结果决定 Tauri 是"继续投入"还是"正式砍掉"。现在这样挂着，等于同时维护两套桌面壳。
4. **签名证书**：拿到 `.pfx` 后一条命令 `npm run sign -- -Pfx cert.pfx -PfxPassword ***`，脚本已就绪。
5. **把纯函数平移到 vitest**：`Attribution`/`interpreters`/`xml` 直接复用现有断言，得到秒级反馈环。
6. **阶段 11 接进 `/perf`**：趋势线 + verdict 徽章 + 变点竖线，成本不高，直接把"能算"变成"看得见"。
7. **`server.ts` 按域拆**（ws / git / perf / plugins / migration），handler 已独立，纯搬迁。
