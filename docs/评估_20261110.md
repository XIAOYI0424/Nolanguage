# 项目评估与整理（2026-11-10）

> 评估对象：Nolanguage **0.7.8** · 基线：`docs/评估_20261107.md`、`docs/评估_20261102.md`
> 方式：读代码 + 跑全量 + 查仓库历史，不采信文档自述
> 结论先说：**工程能力没问题，仓库卫生出过一次事故**——0.7.5 和 11-07 的改动一直悬在暂存区，本轮才真正入库。

---

## 一、最重要的一件事：仓库完整性事故

### 发现了什么

`v0.7.5` 这一版**不存在**。`git tag` 里是 `v0.7.0…v0.7.4, v0.7.6, v0.7.7`——跳过了 0.7.5。而 `CHANGELOG` 里 0.7.5 那一节写着：客户端 8 分片、`server.ts` 按域拆出 `handlers/`、CI 入库、纯函数进 vitest、阶段 11 接进 `/perf`。

查证：

```
$ git cat-file -e HEAD:src/panel/ui/client-assets.ts
→ 不存在
$ git status --short | wc -l
→ 60（57 个 staged，3 个未暂存）
```

**这些文件都在工作区里，全量套件也能跑通，但它们从未进入 Git 历史。** 同一批里还有 11-07 那轮修的三个 P0（`profileResult` 重复 case、DAP 断点时序、终端 cwd）。

### 为什么会这样

我在 11-01 提交 0.7.6/0.7.7 时，`git add` 只列了 `src/debugtool`、`debugtool`、`installer`、`CHANGELOG` 这些路径，**漏掉了 0.7.5 那批 `src/panel/**` 改动**。11-07 那轮则做了"全部 `git add`"但没 commit——两件事叠在一起，暂存区堆了 57 个文件、跨三个版本。

### 后果（比"没提交"严重）

1. **tag 与树不符**：`v0.7.7` 那棵树里没有 `client-assets.ts`、没有 `handlers/`、没有 `ci.yml`，但 CHANGELOG 说它们存在。clone `v0.7.7` 得到的是一个**和文档描述不一致**的项目。
2. **CI 从未执行**：`ci.yml` 只在暂存区，GitHub 上看不到。
3. **风险敞口**：这些改动只存在于一台机器的磁盘上，一次误操作（`git checkout .`、`git stash drop`）就没了。

### 本轮怎么处理

- 57 个文件一次性提交（0.7.8），`CHANGELOG` 里写明补提交范围，不掩盖。
- 版本号推进到 0.7.8：**tag、树、文档三者对齐**，此后 `v0.7.8` 是可复现的。
- 两个旧 tag（v0.7.6 / v0.7.7）保留不动——它们是真实的历史节点，只是不完整；删掉反而更不透明。

## 二、核实：11-07 声称的三个 P0 是真的

评估不采信自述，逐个查了代码：

| 声称 | 证据 | 结论 |
|---|---|---|
| `profileResult` 重复 case，后半段不可达 | `grep "case 'profileResult'" src/panel/ui/client/*.js` → **只有 1 处**（`50-runtime.js:610`） | ✅ 真的 |
| DAP 断点在 `configurationDone` 之后才下发 | `DapClient.start(breakpoints?)` 存在（`DapClient.ts:142`）；`server.ts:1522` 是 `await dap.start({file, lines})`，注释写明"晚到的 setBreakpoints 在 stopOnEntry=false 时已经太晚" | ✅ 真的 |
| 终端 cwd 不跟随工作区 | `handleTerm(cmd, reply, conn, cwd)`（`server.ts:1128`），调用点传 `fs.root`（`server.ts:567`） | ✅ 真的 |

这三个都是"功能看起来有、实际不生效"的静默故障——这类 bug 最值钱，因为它们不报错。

## 三、本轮修掉的三个真问题

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | **vitest 静默丢测试文件** | Vite 转换缓存写在系统临时目录，写失败时 vitest 把该文件从运行里**去掉**，摘要仍显示通过。实测出现"1 文件通过、`phase1.test.ts` 从未运行" | `cacheDir: '.tmp/vitest'`（仓库内），沙箱内外都是 38/38 |
| 2 | **ndebug e2e 竞态** | 示例程序 4 秒结束，`verify-all` 里机器更忙时 watch 还没求值程序就退了 → 偶发 2 条失败 | 目标延长到 20 秒；连跑三次稳定 |
| 3 | **Windows 临时目录删不掉** | 被 kill 的解释器短暂持有 `sitecustomize.py`，`rmSync` 抛 EBUSY → **每次运行残留一个临时目录** | 带退避的重试（8×60ms），清理失败不影响会话 |

第 1 条是这次整理里最有价值的发现：**测试基建会骗人**。一条"通过"的摘要背后可能少跑了一整个文件。

## 五、仍然存在的问题

**P0 · 交付阻断（不是工程问题）**

1. **没有代码签名证书**。`nlg doctor` 如实报 `NotSigned`。自签名链路通，但自签名不解决 SmartScreen。**这决定它能不能给外人用。**
2. **桌面壳押在 Edge 上**。Tauri 搁置（`docs/Tauri搁置说明.md`：运行时 143、机器级、无管理员权限、最小 wry 探针同样渲染不出页面）。

**P1 · 结构**

3. **`server.ts` 的 WS switch 仍有约 900 行**（L1013–1687）。`handlers/` 拆出去了，但分发主体没动——有状态、迁移有风险，两次评估都点了它，两次都没动。这是当前最大的一块技术债。
4. **CI 从未真正跑过**。`ci.yml` 刚刚才入库，`integration` 作业要临时 `npm i --no-save esbuild postject jsdom`，第一次跑大概率要调。
5. **ndebug 只支持 Python**。JS/Go 明确拒绝（诚实），但价值面因此受限。

**P2 · 一致性**

6. **文档门禁缺失**：评估文档已经两次落后于代码（10-27→11-02→11-07 都是事后补）。`项目现状报告.md` 上次也是我手动对齐的。
7. **暂存区习惯**：这次事故的根因是"`git add` 了就算完"。缺一个 pre-commit / pre-push 钩子或"提交前必看 `git status`"的机械约束。
